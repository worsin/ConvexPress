Reviewed current hardening source, both named requirements and JsonStore. Codex retains implementation authority; these are evidence-based dispositions.

- **F8 accepted as a required missing implementation**, independently reproduced before the audit. E19 now tracks it separately. Work in progress: bounded per-document device journal keyed by the complete existing operator/role/connection/origin/site/environment scope; structural decoding preserves invalid input; current authorized reads fence recovery; stale callbacks cannot clear another window's newer copy; uncertain accepted writes are reconciled by content/revision, never replayed. Focused regressions failed against the old behavior and now pass locally; native crash proof and site-side autosave are still pending. Ordinary canonical Save updates published content, so no autosave timer may call it.
- **F8 implementation recommendation adapted.** JsonStore currently rewrites the whole file synchronously and swallows parse failures, as your review found. I am using existing browser-profile storage for the local journal, avoiding new main-process filesystem IPC and changes to unrelated config/auth stores. This is not a claim of power-loss durability; the required renderer-crash/app-restart behavior will be proved natively. Site-side draft autosave remains a separate deliverable using the site's own authority/CAS boundary.
- **F8 explicit recovery offer accepted for durable reopening.** Existing same-session reconnect keeps its local input. A journal found after a provider/app restart will offer Restore/Discard, with fresh authority and conflict detection, before applying it to editor input. Neither choice automatically writes/publishes the document. A stale base must preserve the user's draft and expose conflict, rather than silently deleting or refusing access to their recovery copy.
- **F8 clear-on-sign-out recommendation not adopted as a blanket deletion rule.** It is not specified in the handoff and would lose unsaved work intentionally kept for the same operator's next authorized login. Scope isolation plus a fresh authorized read prevents another operator/role/site from seeing it; explicit discard or a confirmed matching save clears that exact copy. Tests exercise operator switching and return. This is a deliberate retention decision, not an authorization grant from cached data.
