# ConvexPress Standalone MVP Evidence Matrix

Updated: 2026-09-03

## Governing product boundary

This matrix follows the session-authoritative product direction. ConvexPress Standalone is a control-plane shell around multiple isolated ConvexPress website deployments. It is not removed from VirtualOverseer, and it is not a second site-data model. Standalone and VirtualOverseer manage compatible site deployments through the same portable management contract; standalone accepts operator-supplied deployment details while VirtualOverseer may later automate provisioning through MagicDB.

Outer operators authenticate against the VO-compatible control plane. Website customers authenticate inside the selected website deployment. The two identity populations do not merge. Each website environment has its own Convex database and site-local customer data.

UI acceptance is performed only in the real Electron application launched through Playwright `_electron.launch`. Chrome and standalone-browser acceptance are outside this matrix.

## Automated verification

The closing verification set covers:

- control-plane unit/integration tests;
- full site-backend unit/integration tests;
- portable site-contract tests;
- runtime-client tests;
- web component and policy tests;
- desktop IPC and Electron unit tests;
- TypeScript checks;
- admin guardrails, block catalog, and route/navigation smoke checks;
- production builds for the renderer and Electron main/preload processes.

Closing result on 2026-09-03: `bun run test` passed 2,202 tests across 173 canonical source files with 0 failures and 7,564 assertions. Each of the four isolated site fixture copies separately passed its five management HTTP/transaction tests, including selective outer-operator session revocation. The frozen install made no changes, workspace and Electron-main TypeScript checks passed, all three static admin checks passed, and `bun run build` completed both the standalone renderer and Electron main/preload bundles.

The separate `ConvexPress-Website` closeout passed 367 tests across 14 files with 0 failures and 835 assertions, workspace TypeScript, strict lint, a production build explicitly bound to the isolated live-site fixture, the 18-route SEO convention check, the bundle budget (largest client chunk 418.53 kB), and SSR smoke rendering for `/`, `/support`, `/help`, and `/login`. Rendered website acceptance was performed only through Electron; no standalone browser smoke was run.

`electron-builder --mac` produced the x64 `packages/desktop/dist/ConvexPress-0.1.0.dmg` (SHA-256 `4f970248d64c3f4146fd529528f33fb74b066d2e1dbf1ab758c0a05f0039065c`) and arm64 `packages/desktop/dist/ConvexPress-0.1.0-arm64.dmg` (SHA-256 `39cf7b9851d70984ec2b4b42c62ef290b2603b3b82937dc97cc9396631295970`). `hdiutil verify` passed for both disk images. The final arm64 `.app` inside the packaging output passed the packaged Electron acceptance above. These are unsigned, unnotarized development artifacts because this machine has neither a Developer ID Application identity nor `APPLE_ID`; Apple signing/notarization remains a release-credential step rather than an application defect.

The browser-smoke script is intentionally excluded because the user required all rendered acceptance to remain in the Electron Playwright application.
