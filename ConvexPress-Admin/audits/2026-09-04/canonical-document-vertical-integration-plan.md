# Canonical document vertical integration — proposed next milestone

Date: 2026-09-05. Read-only source assessment after root's accepted featured75 gate. This document proposes work; it does not activate a route, schema, endpoint, migration, deployment, or storage model.

## Outcome to build

One disposable **draft page in the existing Aster staging `posts` table** can be opened by an authorized editor in native Admin, edited through the generated canonical field editor, saved with optimistic concurrency, read and rendered by the actual Website under the current authorized native operator, reopened, edited again, and restored through existing revisions. Include a real `core/featured-page` reference to a published page in the same installation. The referenced result must react to target edits and access revocation through the same document query.

Use a small canonical tree: `core/section` containing `core/heading`, `core/paragraph`, and `core/featured-page`. Preserve rich-text marks, canonical `children`, authored IDs, anchors, and valid layout intents. Use actual target media when present and actual absence otherwise. Do not migrate or publish existing Aster pages to obtain this proof.

This is the first complete vertical slice, not completion of the 136-block library. Current evidence is **136 specifications, 75 staged renderers, 61 without staged renderers**; only `content.page` has a implemented staged data adapter. Root accepted 24 browser tests, 600 canonical and 32 featured captures in `output/block-demo/browser-results-featured75`. Root verified the featured75 MagicTables checkpoint: one existing row updated, zero created, all five fields reread exactly, 136 unique rows. Evidence: `renderer75-checkpoint-2026-09-05.json` and `inventory-verified-2026-09-05.json`.

## Proposed implementation sequence and contracts

Names below are proposed, not existing API exports.

### 1. Authoritative canonical storage contract and transition fence

Generate/package the canonical instance validator into the deployable backend using the existing canonical source. Recursion may require a Convex structural envelope plus generated recursive runtime validation; that is acceptable only if every read/write boundary executes the same canonical validator. Do not duplicate per-block schemas by hand.

Use existing `posts.blocks`, `blocksVersion`, and `blocksRevision`; reserve an explicit envelope version (proposed `blocksVersion: 2`, separate from each block's own `version`). Keep legacy storage readable during transition. Retain old fields until lossless migration and historical revision acceptance; canonical records render from the tree exclusively. A new draft should not duplicate its body in TipTap or pageSections.

Implement canonical `layout`, anchor and child constraints at the authoritative tree level. Reuse the existing menu visibility rule schema/semantics as required by the handoff; enforce filtering before resolving hidden nodes and enforce edit locks in mutations. If those semantics are not ready at the first checkpoint, explicitly refuse nonempty visibility/lock with an actionable unsupported-feature error—never drop them, reinterpret them, or narrow the final canonical specification. Validate styles against installed pack declarations and page-wide renderer-owned IDs; current valid attrs cannot bypass those checks.

Audit/fence the actual writer inventory: blocks replace/insert/move/remove/duplicate/update; posts/pages create/update and HTTP internals; autosave; revision restore; import/WordPress sync; content promotion and any generic row authoring path. Metadata-only changes may continue if they retain the canonical tree/version. Unsupported body writers must reject before mutation. Tests must call these real handlers against a canonical row, not just test a helper.

### 2. One authorized current-document read and real data resolution

Proposed `canonicalDocuments.get({postId})` is a registered **authenticated query** for the draft milestone. Resolve the site identity from installation state, get the current `posts` row by ID, require current page/post editorial authority and ownership, reject trash/wrong format, and derive policy from current installed plugins, disabled blocks, and compiled runtime capabilities. No caller-supplied user ID, tree, resolver name, capability list, or site identity can grant access.

Return a closed versioned DTO containing only required document authoring fields, document revision, installation scope, resolved active pack identity/presentation, and the validated data envelope. Viewer binding must be derived from the authenticated server context and live client auth generation; never use a stored attr or parent-provided string as proof. Clear retained results synchronously on sign-out, session/account/site/document changes and permission errors. A query rerun must not render its previous authorized result after revocation.

Move/package the existing `content.page` implementation and its canonical generated contracts into deployable modules without retaining a second independently maintained adapter. The current page is an editor-authorized draft; the **referenced page retains public discovery + membership policy** even for an editor. A private/draft/password-protected/denied/deleted reference yields `{page:null}`, not editorial content. The same current query context is used for every reference. Deduplicate repeated references, bound all materialized policy reads, and return one reactive document/data result. Resolve canonical media identities on the server; never install the BlockDemo resource binder in production.

Do not register a general `resolve(tree, policy, userId)` public endpoint. Public canonical reads can follow behind existing public-content policy once the draft flow passes; they are not needed to expose this disposable draft.

### 3. Conflict-safe canonical save and revisions

Proposed `canonicalDocuments.save({postId, expectedRevision, blocks, ...closedAuthoringFields})` checks authority, expected revision, size/tree/pack/plugin/disabled/lock rules, and referenced-resource validity in a single mutation. The server assigns the next revision. Snapshot the complete previous authoring state using the existing revision system; preserve the parent status, owner, visibility/password, path and integration data. Return the new revision and a stable content digest; identical retried saves should be explicitly idempotent or return an actionable conflict without duplicating revisions.

Use this same operation for canonical autosave if enabled; never send canonical bodies through the legacy title/content autosave. A save transaction is also the validation boundary for previewing saved state.

Extend revision restore for canonical documents with required expected revision, full canonical validation, and safety snapshot. Restore must advance the current revision monotonically. Ordinary legacy revisions remain supported for legacy documents. Crossing canonical/legacy versions requires the reviewed migration/restore path, not automatic JSON guessing. Reopen and compare the complete tree/marks/IDs/anchors/media references rather than only rendered text.

### 4. Actual native editor and Website rendering

Branch the existing page editor on the envelope version before legacy conversion. Reuse `SchemaBlockForm`, generated catalog and RichTextField with a canonical nested outline and a small capability-filtered inserter. Do not build a second visual renderer in Admin. Wire actual same-site page and media pickers, reject stale cross-instance picker results, and preserve tree changes in editor state until the canonical save succeeds. Dirty-state protection, save errors, CAS conflicts and reload are visible and recoverable.

Add `/__preview/document/:postId` as an embedded-only Website route with a neutral server shell and no draft loader. The existing native operator's authenticated site client owns the current document subscription. A separate Website Clerk account is **not** an editor: root live evidence confirms internal roles are limited to local/management identities. Preserve that boundary; the earlier plan's Clerk-editor premise was wrong. See `canonical-preview-auth-prerequisite-outcome.md` and `output/aster-house/canonical-preview/operator-customer-auth-boundary.json`.

Use a per-mount MessageChannel between the native-owned iframe and its parent. Native validates the iframe Window identity, exact configured Website origin, route/document and handshake generation before transferring a port. The child validates its actual parent Window and the explicitly configured/verified native parent origin; no wildcard target origin or arbitrary URL-supplied origin grants backend access. The channel carries only a closed, schema-validated document/tree/data DTO bound to installation, document, revision, and current operator session generation. It carries no token, credential, query function, dynamic resolver name or executable content. The child never authenticates to the backend and cannot request arbitrary protected reads. A top-level visit refuses; another embedding has no source of authorized private data. A challenge prevents stale-window/session cross-talk; it is not authentication by itself.

The native authenticated subscription and current control-plane/site connection state are the authority. Clear/close before site, operator, connection, document or frame navigation changes and on auth/query failure. A short renewable display lease clears retained data if the parent becomes unavailable. Renew only while current authentication/connection and subscription freshness are proved; a local interval alone does not prove server permission freshness. Cross-deployment control-plane revocation is not synchronously readable by a site Convex query: native broker state and bounded reauthorization/lease expiry must enforce that boundary. Record the actual lease window and test offline expiry rather than claiming instantaneous remote revocation. No general management token in URL, storage or postMessage, no new preview JWT issuer, and no alternate customer role mapping.

Private preview is an embedded render of native-authorized data, not independently authenticated SSR or a standalone shared draft link. Its response is neutral/no-store, without draft metadata or static cache entries. Standalone sharing/authenticated SSR needs a separate reviewed product scope only if required, and is not a new prerequisite for native preview acceptance.

Install the real canonical dispatcher/resources/data channel under the current Website pack's page surface for this preview route only. Preserve the ordinary site shell and approved pack isolation, Section defaults and anchors. Core/Aster primitive baseline and opt-in Journal/Depot parts need explicit production installation; do not import the demo gallery or claim palette-only fixture themes as real pack configuration. All imports must pass Website/Worker build closure.

Start with save-first preview: the authenticated Website subscription reads the saved current document and updates automatically. Reuse existing Customizer messaging only for non-authoritative selection/highlight and pack presentation. Unsaved tree preview is a subsequent authenticated, revision-bound contract: it must revalidate the candidate tree under current permissions and resolve its actual dependencies. Never overlay changed reference attrs onto an envelope bound to an older tree. This staged ordering is an implementation checkpoint, not removal of the handoff's eventual live-preview requirement.

## Acceptance before any broader activation

1. Local real-handler tests create a canonical draft in existing `posts`, read it as the authorized editor, deny anonymous/subscriber/wrong owner/revoked users, and preserve same-instance identity. No network/provider calls in tests.
2. Save rich text and nested children, reopen with exact IDs/marks/anchors, edit/save again, and restore the first tree with a new monotonic revision. Stale save and stale restore cannot overwrite newer edits. Legacy writer regression matrix cannot downgrade or strip it.
3. One authenticated document query returns real same-installation featured-page data, image and no-image states. Target title/media edits rerun it; publish/visibility/membership revocation returns no protected data. Duplicate references share a bounded read. Malformed/oversized/uninstalled/disabled/unsupported blocks fail before data work; caller attrs cannot invent resolver authority.
4. Native Admin opens the actual disposable Aster staging draft and its generated editor. Root edits title/rich-text/reference, saves, closes/reopens, changes it again, restores a revision, and reads back the actual backend tree. Record IDs are root-owned acceptance artifacts, not demo fixtures.
5. Root opens the actual staging Website preview inside the native editor under its current authorized operator subscription. It renders the saved canonical tree under Aster and reads real reference data. Signing out clears it; top-level visits and another embedding cannot retrieve the draft. Document/site switch and permission revocation cannot flash prior data. Anonymous HTML/network responses contain no draft content.
6. Root validates responsive 1440/390, keyboard editing/navigation and current reduced-motion behavior, with actual media identity and long-copy states. Existing 75-block browser gates remain a regression baseline, not proof of the new backend/editor flow.
7. Generated canonical/portable/API contracts fresh; backend/Admin/Website types, meaningful handler/DOM tests and Worker build pass. Only root deploys the reviewed schema/backend and publishes the matching Website. Root decides rollback/retention of the disposable draft; no broad Aster migration occurs.

## Remaining full-scope work stays explicit

Complete all 136 real runtime contracts/renderers, actual plugin/provider actions and scoped DTO adapters; unsaved authenticated live preview; user-dependent SSR/session transport; whole-document visibility/lock/style semantics; full nested editor affordances and migrations; meaningful source budgets and production-scale limits; pack-specific treatment acceptance; migration of every legacy content source without loss; revision/promotion/export interoperability; deletion of old models/registries/editors only after parity. The current offline Aster preflight still refuses unresolved field-guide spacing/alignment/ink/font and product columns, and pageSections conversion remains incomplete. No first vertical-slice success licenses silent conversion or sets full-completion flags.

## September 5 correction and transport decision

Root approved native-owned embedded preview after the Clerk denial experiment. Compare alternatives: an extra issuer/code exchange would introduce new credentials, storage and revocation machinery without being necessary for native preview; it also cannot magically query current control-plane authority across deployments. The chosen bridge keeps existing management/local authorization in native, exposes only resolved display data, and makes its bounded stale-display lease explicit. No dependent frontend endpoint is guessed before backend checkpoint A. The eventual unsaved preview contract remains: native submits a validated candidate tree with expected current revision through an authorized backend preview query and sends the resulting exactly bound DTO; never reuse saved data for a changed reference.
