## Next policy read design (awaiting root activation review)

The current `convex/membership/access.ts` uses full rule and grant collections. Use two internal query exports with a narrow known-path contract: rules by exact resource or route index prefix; grants by exact user/status. Each invocation should perform one server-budgeted page (256 rows,512KiB) and throw `MEMBERSHIP_POLICY_BUDGET` for incomplete/split results. Route pattern filtering happens after the bounded route-only index read. Never allow access using a truncated rule/grant list; never cache across shared helper calls that may surround writes in a mutation.

Do not put multiple `.paginate` calls directly into the shared helper: Convex supports one paginated database query per function. Calling these internal reads through `ctx.runQuery` retains the caller transaction with separate function journals. This needs nested query and mutation-read-after-write tests before activation; it is not implemented at this checkpoint.

Primary references: [pagination options and server read limits](https://docs.convex.dev/database/pagination), [official pagination design limitation](https://stack.convex.dev/pagination), and [Convex backend UDF source](https://github.com/get-convex/convex-backend/blob/main/crates/isolate/src/environment/udf/async_syscall.rs) (`MultiplePaginatedDatabaseQueries` guard and fresh nested query journal). These sources support the design; no unsupported private SDK syscall or new dependency is proposed.
