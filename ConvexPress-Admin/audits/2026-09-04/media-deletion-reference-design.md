# Bounded media reference inspection and deletion — proposal, not implemented

September 5. Read-only design against `/Users/worsin/.codex/worktrees/convexpress-hardening`. No runtime, schema, permission or deletion changes were made for this proposal.

## Current behavior and additional coverage prerequisite

`packages/backend/convex/media/mutations.ts:477` soft-deletes to trash after the reference check. Normal deletion refuses any discovered reference. Force requires the current media-delete capability and existing ownership/editor checks, and clears references before deletion. Permanent deletion additionally removes storage, variants and metadata. Bulk handlers allow up to 100 selected media and return per-item results. The daily `media/internals.ts:1680` emptyTrashCron performs the same reference check before permanently deleting eligible trash; it must be included in any repair.

`media/references.ts:38` scans ten source tables (users, posts, products, variants, product categories, albums, album items, KB articles/collections and recipes). Only album items currently use their media-reference index. Whole-table and filtered collects recur per selected media. `clearMediaReferences` later clears scalar fields, filters product gallery arrays, clears nested hero/topic image fields and deletes album-item rows while decrementing album counts.

The inventory is incomplete, independently of bounds: `schema/lms.ts` declares media IDs on courses, nodes, certificates and certificate issues, while `references.ts` has no LMS branch. Variant galleryMediaIds (`schema/commerce.ts:322`) is also omitted. An actual `findMediaReferences` invocation against a local in-memory fixture containing `lms_nodes.videoMediaId` (with requireVideoWatch:true) and `commerce_product_variants.galleryMediaIds` returned an empty array. No live media or customer records were deleted. LMS lesson mutation validation explicitly disallows requireVideoWatch without a remaining video source (`lms/lessons/mutations.ts:64–72`), so a generic force-unset adapter would also be unsafe for that case.

Therefore replacing `.collect()` with truncated reads cannot establish safe deletion. The scanner needs a reviewed coverage inventory, including typed IDs and media-bearing opaque authored content (legacy blocks/TipTap/settings/template configuration). A recognized reference without a reviewed clear adapter must block force deletion with an explicit unsupported-reference error. Unknown content versions/shapes must not be interpreted as no references. Reuse generated block field/reference metadata and existing validated content parsers where applicable; do not create a competing block-name registry. URL-only embeds are a separate coverage policy and must not be silently treated as typed media-ID references.

## Recommended first implementation: bounded atomic refusal, no asynchronous authorization

1. Generate or audit a closed descriptor inventory from the actual schema's media-ID fields. Each descriptor identifies table, indexed scalar path or a reviewed nested extractor, exact reference DTO, and an explicit clear policy. Add coverage tests for LMS and variant galleries before enabling destructive work. Unsupported shapes/adapters refuse; do not silently omit them.
2. Add scalar indexes: users.avatarMediaId; posts.featuredImageId and nested hero.imageId; products.featuredMediaId; variants.featuredMediaId; product categories.thumbnailMediaId; albums.coverMediaId; KB article featuredImageId and collection coverImageId; recipe featuredImageId/scanMediaId. Reuse gallery_albumItems.by_media. Add corresponding reviewed LMS scalar indexes. Convex array membership cannot be solved by indexing the entire array; topics/gallery IDs and opaque authored content require bounded extraction or later reverse-reference rows.
3. Expose paginated **inspection only**, with `{mediaId, descriptor, paginationOpts}` or a closed cursor envelope `{coverageVersion, descriptor, nativeCursor, endCursor}`. The server chooses a descriptor from the allowlist and applies 256 rows / 512 KiB per read. Closed DTO: reference table/document/path, current document revision or deterministic content digest, bounded display label, and clearability reason. Preserve empty/split pages and expose incomplete state. Never accept arbitrary table names, JSON paths or patch payloads. Require the existing appropriate media access policy; any capability split for browsing versus deletion is a separate explicit decision.
4. The actual remove/permanent-delete mutation **does not trust the inspection cursor, completion flag, receipt or client-provided references**. It reauthorizes and performs its own complete reference check in the same transaction as the final writes. For normal deletion, an indexed existence proof is enough to refuse. If any nested source range cannot be completely checked within the budget, return `MEDIA_REFERENCE_CHECK_INCOMPLETE`, with no metadata patches, blob deletion, media-status change or delete event.
5. Distinct internal queries can own their single paginate invocation, as in the already-tested membership policy pattern. Return explicit complete/incomplete plus source-row/byte accounting and compact references; do not use a context proxy. Track a whole-operation budget in the parent in addition to each page budget (proposed 2,000 source rows, 4 MiB source documents and at most 100 touched reference documents). This is a bounded refusal contract, not a claim that every large site can already delete every unused asset. Stop before starting another read when no budget remains; count the materialized document before dependent reads. A fetched oversized document may already have incurred its read cost.
6. Force deletion requires **all** references to be known, clearable and within the operation/write budget before the first write. Reread authoritative records inside that mutation; clear only values still equal to the target media ID. Recompute array matches by value, not stale array indices; preserve unrelated fields and other media IDs. Aggregate multiple references per source document into one validated patch and adjust album counts from rows actually removed once. If a required business invariant would be broken (for example a video-watch lesson with no other video source), refuse force with an actionable affected-document result rather than mutating that invariant silently.
7. Preflight mediaSizes/mediaMeta through their existing by_media indexes under the same complete-read/write budget before permanent deletion; their current `.collect()` calls are not inherently bounded by the comment claiming four variants. Recheck the media and its storage IDs in the final transaction. Storage deletion failures and shared-storage ownership need an explicit error/idempotency contract; the current blanket catches must not turn an unknown failure into a proof of complete physical cleanup.
8. Bulk requests use one preflight plan for the selected set, not a whole-site scan repeated up to 100 times. Preserve ordinary per-item not-found/in-use results where they can be determined safely before writing. An incomplete global inspection refuses the affected operation before any writes. Do not catch a post-write failure and return an apparently ordinary per-item error while committing half of that item's reference clears; unexpected failures must roll back the transaction. This stricter failure behavior needs explicit tests alongside the existing successful/blocked per-item behavior.

Writers that attach media must validate the referenced media in the same transaction. The final mutation can detect references inserted before/during its indexed reads, but cannot prevent a later writer from attaching a deleted ID if that writer only validates the ID syntax. This writer-invariant audit is required for an end-to-end race-safety claim, including the first slice.

This first slice deliberately supports bounded complete cases and refuses the rest. It preserves normal-versus-force intent and current role/ownership rules. It does not create an unsafe “scan earlier, delete later” bypass. Index introduction and scope of newly covered reference adapters require review before implementation.

## Scalable follow-on: maintained reverse references, only after writer coverage

For large nested arrays/opaque content, add media reference edges keyed by media ID and source document (plus path/descriptor/version), with indexes `by_media` and `by_source`. All applicable creation/update/delete/import/clone/restore paths must update edges atomically with the source document, including extension writers and bulk import. Never mark coverage ready just because a backfill finished if a live writer can still bypass maintenance.

Backfill uses durable server-owned progress `{coverageVersion, tableDescriptor, cursor, phase}`. Each transaction reads one bounded source page, derives current edges, replaces edges for each current source document and advances its cursor atomically. Concurrent source writers must participate in the same maintenance protocol; transactions then conflict/retry rather than overwrite fresh edges with a stale scan. A generation change, unsupported content, schema/plugin additions or restore/import that bypasses maintenance invalidates readiness and blocks destructive use until rebuilt.

Once coverage is proven ready, normal deletion atomically checks the exact by_media range and refuses if any edge exists. Force loads a bounded complete edge set and source documents, revalidates each current path/value/business invariant, clears references, removes edges and deletes/trashes the media in the same transaction. Source writers must read/validate the media in that transaction so a new reference racing deletion conflicts or is refused; merely checking an advisory deletion flag that writers ignore is not a lock. An asynchronous UI review never authorizes later deletion on its own.

Avoid making force a multi-transaction detach operation in the first slice: it changes atomic behavior and allows partial authored-content removal. A later durable detachment workflow would need per-media fencing acknowledged by every writer, explicit progress/cancel semantics and a final complete by_media recheck. Until then, an oversized force request refuses and the operator can edit the referenced documents separately.

## Cron and acceptance

The trash cron uses exactly the same authoritative, non-force reference guard and bounded metadata preflight. It skips/refuses incomplete checks instead of treating them as unused. Replace repeatedly taking the first 200 trashed rows with a durable bounded cursor pass; retain a fixed cutoff/query shape for a pass so cursors remain valid, recheck current retention settings and effective trashedAt/legacy updatedAt immediately before deleting, then start a new pass after completion. A status/trashedAt index can avoid newer rows crowding out older eligible trash; legacy missing trashedAt requires explicit fallback handling. No force behavior is added to the cron.

Required tests: real handlers deny unrelated-owner/role cases unchanged; ordinary in-use refusal and unused success; force preserves other references and content fields; typed LMS/variant and nested authored references are detected; required video-watch invariant refuses unsafe clear; more-than-one-page and oversized source/meta evidence causes zero writes/deletes/events; repeated/split/empty inspection cursors cannot authorize deletion; a reference inserted after preview is found by the final mutation; a reference changed since preview is never cleared by stale path/index; bulk does not repeat scans or commit partial clears after failure; cron does not delete referenced/incomplete/recently restored items or starve later eligible rows. Live tests need disposable authored fixtures and explicit root authorization; no such tests were run for this proposal.
