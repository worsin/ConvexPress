## Authoritative scope and decisions

`blocks/core/poll/block.json` previously declared a single-question poll and `forms.poll` without an implemented resolver or voting system. The saved specification now binds `block.id` and adds `responsePolicy: visitor | signedIn`. Its dedicated `poll.submission` capability remains absent from production policy until the live interaction host and acceptance are complete.

Visitor policy means one browser token, or one verified account when signed in; it does not establish one response per human. The future browser host must generate its cryptographic token on an explicit voting gesture, not on render. Signed-in policy requires current active account authority. Token storage/session transition and abuse protection remain implementation work, not accepted guarantees.

Ballot identity hashes the exact question, stable option keys/labels and response policy. Reordering options or toggling aggregate visibility preserves the ballot. Changing meaning opens a separate ballot; restoring the original content returns its original ballot. Copying the page isolates results by the new post ID. Votes are not deleted by authoring edits.

## Implemented

- Two Forms-owned indexed tables: `form_poll_votes` and `form_poll_tallies`. A bounded tally has at most 12 choices. Indexed identity lookup and vote/tally writes share one mutation transaction. Retry returns the original recorded choice without incrementing or changing it.
- Registered `extensions/forms/polls:get` and `:vote`, with explicit runtime validators and return types. Source authorization rechecks the current published canonical page, password, route/membership authority and its deadlines, active viewer, nested visibility and disabled plugins/blocks. Unknown or stale definitions/options refuse before writes.
- Aggregate query returns no counts when `showResults` is false, no voter hashes, and only the requesting identity's prior choice. Corrupt tallies refuse rather than leaking misleading results. Request budgets include source and vote/tally reads. Actual registered tests show read cost unchanged after 40 additional responses.
- Closed portable `forms.poll` contracts and planner validation. A trusted document adapter supplies the post identity, rejects an unsaved question or results disclosure, forwards source password, and participates in the caller's read/authorization budget. Wrong block/envelope/environment is rejected.
- Poll renderer with template Heading primitive, accessible radio choices, keyboard submission, selected state, results bars, pending state, error focus, confirmation focus and repeat-response state. The view cannot create an identity, query or vote by itself; its optional host supplies those operations. Read-only previews send nothing. Result bars animate transforms and respect reduced motion.
- BlockDemo synthetic preview/interactive/error/reset fixture and realistic example questions. Examples explicitly disclose synthetic results. They neither call production handlers nor send external messages.
