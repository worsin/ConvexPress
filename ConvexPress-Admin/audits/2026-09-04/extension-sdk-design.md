# HC2 extension SDK implementation design — September 4, 2026

- Website manifests are pure metadata discovered under extensions and extensions.local. They declare identity/settingsKey/default/dependencies, public route prefixes, surface IDs and view-model names, reusable part IDs, chrome contributions, and Dashboard registry page IDs. Dashboard remains backend-registry owned; manifests reference its IDs rather than duplicate its titles/paths/access policy.
- Replace public enablement's handwritten switch with a pure manifest resolver. Preserve existing fallback behavior during loading, honor canonical settings keys before legacy aliases, require parents, and fail closed for missing/cyclic definitions. A generated static manifest index supports tests and tooling; Vite discovers installed manifests for actual builds.
- Backend extensions gain pure plugin metadata consumed by the existing extension-index generator. New extension defaults/settings keys/dependencies merge into backend plugin helpers and settings defaults automatically. Admin manifests already have a scanner; add parent metadata support. Generators reject duplicate IDs and scaffolding refuses existing files.
- Events reference plugin implements event publication, not a ticket-payment system: draft/published/cancelled/archived lifecycle, unique slug, validated title/description/venue/time zone/start/end, capability-gated admin pagination and editing, explicit public projections, disabled-plugin gates, audit events, and soft archive. Public schedule/detail and Dashboard Events reuse the same model. Add Core events.index/events.detail/dashboard.events surfaces; other packs inherit Core until they provide their own.
- create:extension scaffolds backend schema/query/mutation/plugin metadata, Admin manifest/nav/list/editor, Website manifest/public route/Core surface and tests, then regenerates indexes/catalog mirrors. Use a slug and optional title; no deployment, provider call or browser operation occurs in the generator. Reference and generated layers obey extension-kit contracts.
- Tests cover disablement/auth/publication safety, duplicate slugs, invalid dates and time zones, lifecycle transitions, manifest aliases/parents/cycles, and scaffold validation/no overwrite. Root owns screenshots and live acceptance.
