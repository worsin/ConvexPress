## Contracts and checks

`bun run sync:blocks` in Admin copies only the existing pure Zod schemas into `packages/blocks-catalog/src/generated`; it does not import React editors into Convex or redesign the registry. `bun run check:blocks` now checks generated source freshness as well as existing names, and requires matching Admin/Website schemas for ready portable blocks. Core Website schemas intentionally remain more permissive for historical rendering, so they are not falsely required to be byte-identical to authoring schemas. Adding or changing a block requires regeneration before backend publication. Zod uses the workspace's existing catalog version; no dependency upgrades.

Before repairs, real-handler regressions demonstrated unknown writes resolving successfully, nested disabled duplication resolving successfully, missing portable AI contracts and broken bracket extraction. Additional red tests demonstrated dropped nested output and two writes for one AI replacement. After repair, **26 tests pass / 145 assertions** across block contracts, publication recovery and reserved page-route handlers. All 54 AI examples validate against their actual schemas; tests verify nested unknown attrs are stripped before storage, existing disabled edit/move remains available, and concurrent editor changes survive AI generation conflicts.

Admin web and catalog package typechecks, block catalog/generation checks and scoped diff checks pass. **Integrated backend typecheck now passes** (session 22695, exit 0, empty `/tmp/block-backend-types-final3.log`). Coordination with the commerce agent resolved generated API inference cycles through explicit finite function contracts; this agent annotated KB `syncArticle`, WordPress `testSiteConnection` and the internal `getSiteWithCredentials` query, preserving runtime bodies and removing their obsolete inference suppressions. Commerce owns final compact API regeneration/caller parity. No database migration or new API arguments are required. Evidence: `/tmp/block-contracts-red.log`, `/tmp/block-ai-red.log`, `/tmp/block-contracts-green.log`, `/tmp/block-backend-types-final3.log`, `/tmp/block-admin-types.log`, `/tmp/block-catalog-types.log`.

Remaining design/performance work is deliberately separate: actual nested editing/rendering, consolidated content migration, block preview/undo, pack-specific block treatments, shared SSR data resolution, lazy loading and runtime compositions. These require a scoped design and acceptance decision rather than automatic adoption of the research proposal. Live AI-provider generation has not been exercised; provider calls in regression tests are mocked at the real action boundary. No provider, native, deployment or browser operations were performed by this agent.
