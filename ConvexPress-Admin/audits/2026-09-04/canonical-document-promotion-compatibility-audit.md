## Full interoperability implementation (beyond temporary refusal)

1. **Versioned portable authoring contract.** Extend the shared promotion page/post contract with a discriminated legacy/canonical body envelope, explicit blocksVersion, and an authoritative generated canonical tree validator. Keep source blocksRevision as immutable review evidence, never assign it to target. Add canonical schema/catalog and installed capability compatibility evidence to the reviewed manifest/plan. Bump the promotion wire version or negotiate explicit supported envelope versions; a broad schemaVersion equality alone is insufficient. Validate at exporter, CP validateExport/receipt serialization, target dryRun/apply/rollback, and Admin dataJson parsing. Older receipts remain immutable and either retain their old adapter or require new review; never reinterpret them under changed hashing/validation rules.
2. **Generated reference adapter.** `exporter.ts:164–299` currently guesses dependency fields by name; block inspection/remapping at 405–480 traverses innerBlocks and rewrites IDs. Build the canonical adapter from generated field/reference metadata and traverse children using the same whole-tree validator. Enumerate page/media/product/course/form/plan references, nested arrays and visibility/lock policy dependencies with explicit supported adapters. Map source resources to target stable identities, preserve rich-text links/marks, validate target references after substitution, and retain missing/disabled dependency issues. Define whether block IDs remain document-local or are remapped; if remapped, persist the bijection and update every block restriction/reference consistently. Anchors and renderer-owned IDs must remain valid and collision-free. Do not regex-rewrite arbitrary authored strings or erase user/provider references to make validation succeed.
3. **One canonical mutation service.** The target adapter should call an internal same-transaction authoring service shared with save/restore, not the legacy public save action and not independent duplicated validation. Run target policy/media checks after resolving IDs, snapshot previous authoring, write v2 with target revision + 1, and retain promotion's atomic mappings/backups. CP already re-exports source and checks immutable manifest/sourceRevision hashes before dispatch (`contentPromotion/apply.ts:68–75`); site apply already rebuilds and hashes the target plan (`operations.ts:335–342`, `planner.ts:473`). Preserve both. Canonical rules/capability revisions must become plan dependencies so a disabled block or changed style policy after review also invalidates apply. No outbound event/provider replay as a side effect of importing historical content.
4. **Readable review + exact identity.** Admin `PromotionAuthoredContent.tsx` currently safely renders a bounded TipTap subset and explicitly directs block content to Website preview. Extend it with a schema-validated canonical outline/text/marks and reference changes; keep exact validated JSON secondary. Actual appearance remains the real canonical Website preview, with current viewer authorization. Do not pass resolved viewer data or signed credentials through authored manifests. Source/target catalog hashes, document versions, references and policy evidence belong in the fingerprint; transport timestamps/temporary download URLs do not.
5. **Acceptance graph.** Source export → CP review → target dryRun → CP re-export → target apply → target canonical read → Website rendering must preserve a nested section/heading/rich paragraph/featured-page tree, marks, IDs/anchors/layout and correctly mapped target media/page references. Prove stale source, target edit, revoked permission, disabled runtime, missing referenced page/media and changed style policy fail atomically; repeat exact receipt creates no duplicate content/history/outbound work. Follow with second edit and canonical rollback/restore with monotonic revisions. Include empty v2 documents, optional children, unsupported block semantics and mixed legacy/v2 selections.

## Full snapshots are a distinct recovery path

CP `operations/replacementSafety.ts:6–25` rejects full `site.clone`/`site.promote` and requires exact same-environment identity for restore. `operations/internal.ts:345–357` checks contract/schema/engine compatibility. `operations/actions.ts:321–376` preserves target management tables and imports via the provider's `replaceAll` path (`snapshotImportApi.ts:190–195`). Both in-memory `snapshotRestoreArchive.ts:217` and active streaming `remoteSnapshotArchive.ts:508` preserve raw source authored rows; they do **not** silently project posts into legacy content. This is a positive control, not a content-promotion adapter.

However, archive inspection validates archive integrity/identity/metadata, not canonical row semantics or current attachment availability; provider import bypasses all application write guards. Before canonical disaster recovery is production-complete, extend snapshot manifest/preflight with supported document-envelope/catalog versions and bounded streamed posts/revisions validation plus media/storage closure. Preserve opaque fields byte-for-byte for supported versions; reject unsupported versions explicitly. Require a target write-maintenance boundary through import and post-import validation/reconciliation; invalidate old editor sessions/revision tokens with an installation restore epoch, because restoring historical counters is intentional in disaster recovery. Rebuild/verify media reference readiness before enabling attachment deletion/writes. Test both archive-preparation implementations, malformed nested canonical rows, orphaned media, same-version valid raw roundtrip, unsupported newer format, old-client CAS after restore, and cross-environment refusal. Do not use restore as fallback for a blocked authored promotion.

Offline `scripts/blocks/content-migration.mjs:21–86` is a deterministic candidate generator retaining source hash/original revision, not a database writer. Its future activation must use the shared canonical service with expectedRevision/source hash, same-site identity and media checks, then retain the original revision until real rendering acceptance. Existing unresolved conversions remain actionable refusals.
