# Physical commerce catalog promotion outcome

Implemented in canonical source and verified offline. No deployment, provider calls, live reads/writes, browser, native process, commit or push was performed by this agent. Design: [content-promotion-commerce-design.md](content-promotion-commerce-design.md).

## Delivered

The strict shared manifest and canonical export/review/apply handlers now support `product`, `productCategory`, and `productVariant`. Existing selection payloads remain valid; optional `productIds` and `productCategoryIds` select a concrete catalog graph. Supported product-showcase, featured-products and category-tiles blocks discover a bounded published catalog and include its category ancestry, variants and media in the reviewed unit. Dynamic catalog discovery reviews the whole bounded published catalog, not just the currently displayed cards. Explicit product/variant references and product slugs discover their authored dependencies.

Commercial fields are explicit: minor-unit prices with currency, sales/windows, SKU, physical dimensions and tax flags, authored titles/descriptions/publication, categories, media, and local option names/values. This is a complete allowlisted authored snapshot: omitted optional authored fields such as a prior sale price are cleared, and review's changed-field list includes those clears. Local option IDs are reconstructed on new targets and preserved by normalized name/value identity on updates. Target media/storage, category paths and variant/product IDs are remapped. Direct and ancestor category counts update atomically, with all affected categories reviewed and backed up.

New physical products start with tracked zero stock and backorders disabled. New variants start with managed zero stock and out-of-stock status. New variants under an existing untracked parent are rejected because the canonical cart otherwise bypasses variant stock checks. Existing inventory quantities/policy, provider identifiers, delivery metadata and author identity stay target-owned. No users, customers, carts, orders, payments, memberships, subscriptions, submissions, delivery queues or runtime tables are copied. No events, hooks, schedulers, outbound integrations or search indexing jobs are replayed; search text is derived locally.

Review refuses disabled target commerce, target currency mismatch, duplicate/claimed SKUs, removal/change of an established SKU, ambiguous selections, invalid sale windows/currencies, malformed option/default collections, wrong reference kinds, unreviewed target variants/category ancestry, existing category moves, and incompatible product/delivery types. Existing target fingerprints, expiry, operator checks, explicit live confirmation, idempotent receipts, atomic apply and guarded update-only rollback remain intact.

## Runtime prerequisites and remaining scope

Root must deploy the updated site code and shared package to both source and target before using catalog export/apply. This adapter adds no tables beyond the already activated promotion receipts/mappings/backups and requires no data migration or provider configuration. Commerce must be enabled on the target and its configured currency must match the reviewed prices. New stock must be configured separately through normal commerce APIs; promotion intentionally creates no sellable inventory.

The current schema has **no product-tag table or assignment model**. A tag adapter cannot be implemented without inventing a new content model, so tags remain explicitly unsupported. Digital/download/license/external delivery, bundles, global attribute/term catalogs, shipping-class/package associations, paid plan/certificate/assessment structures still need dedicated adapters and reviewed target bindings. The follow-up [learning adapter](content-promotion-learning-outcome.md) now supports courses, curriculum nodes, prerequisites and manual/existing-bound membership plans. No source-owned provider identity or billing linkage is synthesized.

Collection deletion, category subtree moves, created-record rollback/reference cleanup and uploaded-blob cleanup remain outside this adapter. Limits remain **100 authored records / 500 KB UTF-8 per atomic unit**, with bounded catalog/variant inspections. Large-graph chunking, durable orchestration/leases, resumable media transport and whole-job reconciliation are still separate work. Source/target live preservation and rendered Aster catalog acceptance remain root-owned and were not claimed by offline tests.
