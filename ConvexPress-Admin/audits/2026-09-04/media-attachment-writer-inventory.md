## Existing reference scanner and integration implications

[media/references.ts:37](/Users/worsin/.codex/worktrees/convexpress-hardening/ConvexPress-Admin/packages/backend/convex/media/references.ts:37) scans users, posts legacy featured/hero/topics, commerce products/gallery arrays/variants/categories, gallery albums/items, KB featured/cover and recipes. The function ends at line246. It does not traverse posts.blocks, serialized editor content, pageSections, settings/appearance drafts, revisions, lesson snapshots or the broader LMS/event payloads. Its “every system” comment is not evidence of exhaustive current coverage. Gallery junction lookup already uses by_media; most other current checks are collection/filter scans. A reverse index cannot be declared complete merely by migrating this list.

[media/references.ts:260](/Users/worsin/.codex/worktrees/convexpress-hardening/ConvexPress-Admin/packages/backend/convex/media/references.ts:260) force-clear is another attachment writer: scalar clears, product gallery filtering, hero/topics replacement and gallery item deletion/count decrement must update any new edges atomically too. Historical full scans cannot serve as a bounded backfill without completion/error signaling. The current media.attachedTo first-use field is distinct bookkeeping; never use it as proof that no other owner exists.

For each owner write, derive old and complete candidate reference sets, validate added/retained targets according to the agreed lifecycle policy, and replace its reverse edges in the same transaction. Removal-only operations must be able to shed stale references safely. Unknown or unsupported structured payloads need an explicit policy; recursively treating every string as an ID risks false edges, while checking only known top-level fields misses real content references. Auth owns the guard/writer implementation and extraction contract.

The general/template settings representation can retain multiple inactive pack configurations. Decide whether those and private drafts intentionally retain media; changing that policy silently during deletion would surprise authors. Revisions and rollback backups pose the same issue: at minimum validate on restoration, even if they do not retain a hard deletion edge forever.

## Full snapshot boundary

[snapshotImportApi.ts:190](/Users/worsin/.codex/worktrees/convexpress-hardening/ConvexPress-Admin/packages/control-plane/convex/operations/snapshotImportApi.ts:190) sends `{mode:"replaceAll",format:"zip"}` to Convex's import API, then performs that import. This path is deliberately separately authorized; it does not call product/gallery/settings mutation helpers. A restored database can contain old or incomplete reverse-index tables. Schema version alone does not prove those edges were rebuilt. Require a reviewed import/backfill completeness gate before a deletion implementation relies solely on the index.

## Targeted regression cases for auth implementation

- Deleted, trashed and pending-deletion media supplied directly to product featured/gallery, variant and category writes; rejected transaction must leave owner and edges unchanged.
- Gallery missing image, non-image and inactive image; replacing an item array must not remove old items on a rejected new ID.
- Two owners reference one media; replacing/removing one owner retains the other's edge. Force-detach must reconcile both data and edges.
- Nested block array references, retained template values and inactive packs; draft publication/import must not bypass guards.
- WordPress mapping found by an earlier action but media removed before internal upsert; fail at the upsert transaction.
- Revision/lesson/promotion rollback snapshot refers to a now-deleted file; no stale reference resurrection.
- Promotion target media already exists in a disallowed deletion state while its bytes still exist; neither planner acceptance nor media activation should bypass the deletion fence.
- Historical/raw snapshot with missing edge-index completion receipt; deletion must fail closed until bounded reconstruction is proven complete.

Coverage limits: this inventory did not claim every backend writer was enumerated. Auth is independently auditing remaining media/core writers. It did identify direct write bypasses that a shared public mutation-only fix would miss. Current generateVariants does not write a featured image; it is not a missing media writer.
