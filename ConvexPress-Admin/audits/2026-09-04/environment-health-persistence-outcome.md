# Environment health and contract evidence persistence

Implemented locally; no live calls or deployment by this agent. Root owns native acceptance.

The connection Test previously discarded the validated management health response, wrote only connection history, and returned healthy after the signed controller probe regardless of the reported runtime state. EnvironmentCard correctly reads the separate website-instance health/compatibility/version fields, which were never updated by Test. Scheduled fleet health similarly discarded versions. Existing connection history cannot recover those missing versions.

Changes:

- `packages/control-plane/convex/connections/actions.ts` retains the complete health response and publishes it only after the existing signed controller authority exchange succeeds. HTTP 200, malformed JSON, wrong website/instance, or failed authority never establishes healthy status or runtime compatibility. Degraded/unhealthy component reports persist degraded and return an actionable failure rather than a success toast.
- `connections/healthProbe.ts` shares an 8-second, 64-KiB streamed JSON probe, with strict schema and exact website/instance verification. `healthEvidence.ts` derives compatibility using the shared contract compatibility implementation and records the actual contract/schema/engine versions. Reported component status must also be healthy for the aggregate environment to be healthy.
- `connections/mutations.ts:recordHealth` reauthorizes the operator and parent hierarchy at completion. The connection must still be active, hold credentials, and be the environment's current connection. Organization/business/website stamps, connection revision, credential IV and the full target fingerprint (instance revision, identity, all origins, kind) must match. Monotonic completion revisions reject a second stale concurrent result. Late failures cannot revive revoked connections or write to reconfigured/replaced targets.
- New/rotated controller envelopes and revocation invalidate previous connection health. Enrollment alone continues to mean connected; it does not fabricate a signed health check. A fresh Test supplies verified environment evidence. Unreachable observations preserve the last verified version/compatibility evidence.
- `fleet/health.ts` and `fleet/jobs.ts` now preserve and validate the complete management health response under their existing policy lease, live authorization, hierarchy and target guards. Fleet probes report public runtime health; they do not create authority sessions or claim the controller key was verified. Healthy/degraded/unreachable fleet observations remain distinct.
- `apps/web/src/control/sites/EnvironmentCard.tsx` retains Test/Rotate/Revoke for active credential-bearing error connections, labels them as needing attention, and keeps Open disabled until connected. This permits recovery after a transient failed test.
