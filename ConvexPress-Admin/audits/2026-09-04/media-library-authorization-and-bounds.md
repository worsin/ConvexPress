# Site media authorization and scan audit — September 5

Scope: site backend media queries, upload/update/delete guards, and current Admin/Website consumers. This is not the controller media-transfer protocol. Source reviewed in `/Users/worsin/.codex/worktrees/convexpress-hardening`; no live calls, provider operations, deployments or customer data changes were performed by this agent.

## P1: library reads bypass capability revocation and account status

Before the repair, `packages/backend/convex/media/queries.ts` `get`, `list`, `counts`, `getByIds` and `getUrl` only called `getCurrentUser`. `helpers/permissions.ts:239` returns an existing local/Clerk user without applying account status; `requireCan` checks active status, the resolved active role, membership capability policy and management-session capability restrictions. The media detail query returns the entire authored media record, all `mediaMeta`, and uploader display name falling back to email. Batch/list queries also return whole media records. The schema documents EXIF, crop and edit-history metadata; the finding does not claim any particular live secret is stored there.

An in-memory invocation of the actual registered handlers proved that a valid Clerk identity with an active but capability-empty customer role received metadata, uploader email fallback, trashed list/batch data and counts. A banned Clerk user received the same responses. In the same fixture, actual `requireCan("media.read")` refused; update and upload-URL mutations also refused. This was direct backend-handler evidence, not a UI-only navigation claim.

Repair: each of those five library queries now calls `requireCan(ctx, "media.read")` before media/storage reads. Anonymous requests now receive `UNAUTHORIZED`; banned/inactive or insufficiently privileged requests receive `FORBIDDEN`, rather than misleading empty/null library results. Authorized missing-item behavior remains null. No default roles, public asset URL policy, schema, exports or query arguments were changed. Existing broad query return validators remain separate contract work, not claimed fixed by this guard.

Default Subscriber explicitly includes `media.read` in `seed/roles.ts:422`. Therefore default customer library reads are existing intended policy, not automatically a vulnerability. Admin navigation has a separate route guard; that is not backend authorization. The Website `dashboard/pages/courses/CoursePlayerPage.tsx:134` and Admin learner/player renderers call `get` for a lesson's media URL. They retain access under the actual built-in Subscriber capabilities. Restricted custom roles now honor their configured denial. Any future policy removing customer library access must first migrate these consumers to an appropriately scoped rendering DTO; it must not remove capabilities blindly.

`getPublic` and `getSrcSet` are intentionally public rendering endpoints. They remain unchanged. `getPublic` excludes uploader/private metadata and refuses trashed assets. Public storage URLs are not claimed secret, and this repair does not revoke already-issued/public URLs. The existing difference whereby `getSrcSet` does not check trash is not presented as private-file access control.

Verification: new registered-handler tests failed before the guard (4 denial cases failed; 3 intended-access controls passed). After the guard, the media test directory passes 8 tests / 59 assertions. Every denied state exercises all five actual handlers and verifies no media-table/storage read occurred. Positive fixtures use `BUILT_IN_ROLES`, not handwritten stand-in capabilities, for active Subscriber and local administrator. Public projections remain available to anonymous, banned and capability-empty fixtures and omit private fields. This is local source verification; root deployment/native acceptance remains separate.

## P2: counts and search materialize unbounded data

`media/queries.ts` `counts` collects all six media-type indexes, the current uploader index and the trash index. The six types partition the entire media table; additional queries reread subsets. Using indexes here does not bound the full records read. An actual-handler fixture containing 1,000 media records (all owned by the caller, 200 trashed) performed 8 collects and materialized 2,200 records to compute the counts. This is an instrumented local fixture, not a measured production threshold failure.

The `list` search branch calls `searchQuery.collect()` before slicing an offset-based numeric cursor. An actual-handler probe requested 20 results but materialized all 1,000 supplied search matches. Its comment saying search cannot paginate is false for the installed Convex API: `withSearchIndex` returns `OrderedQuery`, which exposes `paginate`. Query `numItems` currently accepts arbitrary numbers, and batch lookup accepts an unrestricted array. These are separate from the implemented authorization guard.

## P2: search and ordinary listing disagree on filters

The search branch returns before the shared trash/date/MIME/unattached filtering. A synthetic search result fixture requesting active PDFs after a later date received trashed JPEGs from before that date. The fixture adapter supplied known matching-title search results; the actual handler performed the early return. Ordinary listing also selects media type/uploader branches before status, and its residual predicate does not enforce status, so combined filters can be ignored. Admin `components/media/MediaListTable.tsx` supplies search/type/uploader/unattached filters and consumes counts independently; pickers additionally supply media filters.

## P2: destructive reference inspection scales with unrelated content

`media/references.ts:38` `findMediaReferences` performs whole-table or post-index-filter collects across users, posts, commerce products/variants/categories, galleries, knowledge base and recipes. The posts scan (`:63`) materializes authored documents even when no media reference exists. `media/mutations.ts` calls this before single remove/permanent delete and once per item in bulk delete/permanent delete (up to 100 items), multiplying the work. The reference helper currently propagates failures; this audit does not claim it silently authorizes deletion when a scan fails.

Upload/update/delete capability gates and own-media/editor checks exist and were retained. The destructive scan issue needs its own fail-closed design: indexed scalar references plus complete bounded/resumable inspection of nested references, with authoritative revalidation before deletion. A limited or truncated list must never become proof that media is unused. No reference/deletion code was changed in this repair.

## Proposed next slice: cursor/filter/count projection, not yet implemented

1. Retain `list`'s public function name and argument meaning. Replace numeric search offsets with actual Convex search pagination and reject invalid page sizes (proposed 1–100 integers). Apply a server-owned per-page rows/bytes budget rather than accepting a client override. Explicitly validate returned pagination metadata including split hints. Native cursors must be scoped/reset when filters change; old offset cursors must fail with a clear reload path.
2. Build one normalized filter predicate used by both paths. Push supported equality constraints into existing indexes/search filters; enforce every remaining supplied filter on the bounded returned page. Empty matching pages with `isDone:false` remain traversable and visibly incomplete. Do not fetch unbounded pages in a loop to make a page look full. Describe these as per-page bounds, not a total-query traversal bound.
3. Introduce a separately named, capability-gated paginated usage/count projection with a closed DTO containing only media ID, media type, trash status, whether it belongs to the current reader and whether attached. One server-budgeted page per invocation; no new aggregate table or dependence on all media writers. The caller accumulates unique IDs and replaces an ID's projection when replayed, preventing duplicate counts. Document how query invalidation/restarts clear accumulated state; do not claim a snapshot-consistent fleet-wide total across independent calls.
4. Migrate the sole current `counts` UI subscriber in `MediaListTable` to the projection, showing “counts loading / counted N loaded items” until complete, with an explicit continuation control. Incomplete numbers must not drive exact total-page navigation. Keep list pagination separate from global tab-count progress. Reset both on site/session changes; reset list cursors on search/filter changes. Use cursor navigation and honest empty-page continuation instead of assuming any empty page means completion.
5. Keep the existing `counts` export for compatibility. After migrating known callers, either implement a bounded exact response for a complete small first page and an explicit budget refusal for larger libraries, or adopt a deliberately versioned compatibility plan before changing its return shape. Do not silently cap its existing exact counts. Apply explicit length caps to `getByIds` separately without changing its ordering/null semantics.
6. Tests: actual handlers across multiple pages and filtered-empty intermediate pages; combined status/type/uploader/date/MIME/unattached filters; search cursors; maximumRowsRead/maximumBytesRead options and split behavior; invalid page sizes; all current denial controls; projection accumulation/replay/reset and incomplete labels. Large-fixture tests distinguish bounded returned rows from underlying scan/byte budgets. Root native acceptance must verify search, picker selection, loading counts and environment switching.

Exact budgets and export compatibility are review points for that next implementation. No P2 completion, aggregate-read bound or deletion-safety completion is claimed here.

## P2 implementation checkpoint

Implemented the reviewed next slice in `media/libraryRead.ts`, `queries.ts`, `validators.ts`, Admin media views/pickers, Website FooterRowsSettings image picker, and the manual promotion source catalog. All existing media query exports are retained; the additional `countDocuments` export returns a closed compact DTO and full pagination metadata. Official pagination options now permit native endCursor/id split handling. Clients cannot raise the server 256-row/512-KiB page budget; requested page size is an integer from 1 through 100. `getByIds` refuses more than 100 IDs, preserving order, duplicates and missing-ID nulls. The legacy counts response remains unchanged when one bounded 100-item page is complete and unsplit; otherwise it refuses with `PAGINATION_REQUIRED` (or `MEDIA_PAGE_BUDGET` for malformed/oversized evidence).

Full-text matching and relevance are preserved. **Convex does not enforce maximumRowsRead/maximumBytesRead for search queries**, as both the installed SDK and current [official PaginationOptions documentation](https://docs.convex.dev/api/interfaces/server.PaginationOptions) state. Native search pagination replaces the unbounded collect, but this implementation does not claim a pre-read full-text scan bound. Search input is limited to 256 characters. Every fetched media page is measured with official getDocumentSize before uploader/storage enrichment; a single oversized document is explicitly refused because splitting cannot make it fit. SplitRequired rows are withheld pending a valid split; both required and recommended split cursors must make progress relative to start/end/continue cursors. Oversized unsplittable evidence is refused. Unique uploader documents have a separate 512-KiB cumulative post-read budget, and enriched responses have a 1-MiB bound. Authorization/shared policy reads and the cost of the currently fetched document are not claimed covered by those post-read checks.

The same full predicate applies status/type/uploader/MIME/date/attachment/trash constraints in indexed and search paths. Residual filtering occurs after one bounded page, without an unbounded refill loop. Empty intermediate pages preserve continuation. Admin main list, inline/editor/LMS pickers and recent uploads now use native split-aware pagination with explicit continuation controls. Website footer image selection does likewise. Main list has no invented total/page-count pagination; count badges appear only when counting is complete, while partial progress says totals incomplete. Count projection merging deduplicates IDs and replaces repeated projections; native pagination resets on changed query arguments, and the library is keyed to its current user within the existing per-instance provider. The manual promotion catalog refuses SplitRequired results instead of skipping their incomplete range. Scoped media/image boundaries keep budget/authorization/query-rollout failures local and do not expose raw exception details.
