# Canonical publication and public reading: source checkpoint

The canonical backend now exposes `setPublication({postId, expectedRevision, status, scheduledAt?})` alongside `getForRender({postId, password?, refreshKey?})`. Publication accepts draft, publish, future and private. A future transition requires a finite future deadline; other transitions reject a supplied deadline. Every transition requires the existing page/post publish capability, editorial access, exact current revision, and current generated tree, resolver, media and presentation validation. A changed transition preserves a complete prior authoring revision and advances the current revision. Published/future/private documents remain available to the canonical editor; saving or restoring them also requires publish capability. Legacy writers cannot change canonical body, visibility, password, publication timestamps or schedules without the internal exact-candidate permit.

Private `canonical-document-v1` now reports the actual four-state status and `document.scheduledAt?: number|null`. Optionality accepts already deployed older DTOs; the new server always emits the actual deadline or null. Public ready envelopes explicitly exclude status, scheduledAt and editorial lock metadata. The public result is separate, closed and viewer-bound: anonymous/public ready content includes only validated display tree/data/resources; password/member refusal includes only permitted teaser metadata and restriction flags. Password verification is server-side. Existing public page/post projections suppress raw v2 and fallback bodies and expose the version discriminator for the dedicated reader. Website integration belongs to the content owner; this backend checkpoint does not itself prove deployed rendering.

Scheduling uses the existing scheduler and exact stored deadline. Rescheduling cancels the identified prior pending job; returning to draft/private/publish cancels it. At execution the internal job requires the still-current future state, exact deadline, due time, active source author, and currently valid tree/resources/presentation. It publishes once with a fresh canonical revision. This honors the persisted publication intention without impersonating or reviving an expired interactive session. An unavailable author or invalid current content refuses atomically. A canonical execution without the deadline binding cannot publish.

Publication event emission uses the existing event engine and counter update. Its optional request-local ledger measures raw returned listener documents and refuses a complete active inventory above 1000 rather than silently dropping listeners. Ordinary event callers retain existing behavior. This is a bounded response/post-read size check; no claim is made that full-text or arbitrary engine scans are bounded by the returned DTO. Every dependent canonical read uses the existing ledger. The initial scheduled post is loaded by the existing internal caller before being recorded by the canonical ledger.
