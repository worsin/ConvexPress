# Membership policy reads — implementation awaiting runtime acceptance

`packages/backend/convex/membership/access.ts` now obtains rules and active/grace grants through the internal-only `membership/policyReads` handlers. Each handler performs one indexed database page with server-owned limits:256 rows and512KiB read. A partial page, recommended/required split, split cursor, oversized page, or raw returned-document bytes above512KiB throws `MEMBERSHIP_POLICY_BUDGET`. No incomplete evidence becomes an allow decision. Return validators reuse actual table field validators and project only the fields the existing evaluator needs; unrelated grant metadata/source references and audit stamps do not leave the internal read.

Route reads use the existing `by_resource` prefix `resourceType='route'`, then the existing pattern/specificity rules. Exact resource reads bind both indexed fields. Grants bind exact user and active/grace status. Existing expiration/grace/capability semantics remain in the evaluator. There is no cross-call cache: grants/rules changed earlier within a mutation are immediately reflected.

The handlers are called through `ctx.runQuery` because Convex allows one pagination journal per function. This separates their journal from each other and from paginated public callers while retaining the transaction. Registered test fixtures remain outside the deployed `convex/` tree in `membership-policy-foundation`; no public policy endpoint was added.
