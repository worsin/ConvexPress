# Current-document navigation data — source integration

The allowlisted canonical data registry now includes `content.breadcrumbs`, `content.anchors`, `content.headings` and `site.info` alongside `content.page`. Authoritative navigation argument/result schemas and tree helpers are copied by the existing exact portable/deployed generator. `ResolverName`, `ResolverArgsByName`, `ResolverResultByName`, correlated `DataBinding`/`ResolverJob` and discriminated `DataEntry` preserve the resolver-to-DTO relationship. The envelope validates each literal resolver with its matching result schema; a result from another resolver cannot be substituted.

The planner binds only generated spec arguments, preserves the existing complete-tree/node/depth/eight-job/output reservation limits and deduplicates equal jobs. The resolver refuses a missing trusted navigation reader before any page-data call. Existing content.page reader signature is retained, with an optional separate navigation reader. All raw result and total envelope byte checks still apply, and the installed consumer trust gate verifies exact scope, block/version, binding key and result target.

Both private projection/save validation and the separate public ready projection supply the actual current post plus the validated tree. The private path supplies the prepared title during save validation. The server adapter uses the same request-local total read ledger and source byte ledger as page resolution. It never takes a user-supplied document/ancestor/function reference. Ancestors are bounded and evaluated with the existing public discovery policy; a hidden ancestor stops traversal. Site info reads the actual indexed general settings row and returns only the closed name/tagline/logo projection. There is no secret/default-settings object in its DTO.

The content owner owns renderer, tree anchor, semantic filtering and navigation adapter tests. Shared source verification includes actual registered initialize→save→get proving the prepared title, exact authored heading anchor, public settings projection with a secret-like field excluded, and direct unauthorized get refusal. Pure tests cover all four correlated DTOs, deduplication, forged result type, missing-reader zero calls, injected instance data descriptors, and result overflow. Combined canonical foundation/handler tests pass 67 / 466 assertions, block tooling passes 56 / 4351, backend TypeScript and check:blocks are green. No live deployment or browser acceptance is claimed by this source checkpoint; root owns that gate and the content owner provides the four new rendering surfaces.
