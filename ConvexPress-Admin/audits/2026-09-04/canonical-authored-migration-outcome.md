# Authored migration: first implemented lifecycle slice

The canonical service now exposes `prepareMigration({postId})` and `migrate({postId, expectedRevision, expectedAuthoringDigest, expectedCandidateDigest, expectedPresentationRevision})`. Review returns a closed `canonical-migration-v1` result with exact source identity/revision/digest and an existing canonical document candidate. The server independently converts and validates the current source again during commit; the caller cannot submit an arbitrary tree as a migration proof. Both operations recheck editorial authority and complete current source reads. Commit preserves the full prior authoring snapshot, routing, restrictions and unrelated metadata, and advances the current canonical revision through the same media/fence/CAS service.

Implemented document conversions preserve paragraph boundaries including blank paragraphs, inline marks and hard breaks, heading levels/marks, flat ordered and task lists, literal code and horizontal rules. Stable block IDs derive from the persisted document ID and source path. Every converted value passes the actual discovered generated schemas, then the full tree validator. No HTML execution, text flattening, whitespace trimming, unsupported property stripping, or partial candidate return occurs.

Unsupported nested/multi-paragraph lists, non-default ordered starts, rich blockquotes/tables, external image source import, legacy block treatment conversion and structured blog sections remain required adapters. Existing generated field limits and total tree bounds are enforced rather than silently splitting authored structures. These are explicit remaining migration work, not completion of the accepted lifecycle.

The old offline preflight's source selection was corrected: public blog surfaces prioritize meaningful hero/topics/summary/sources before article text. A structured article now refuses that earlier incomplete converter rather than replacing visible sections with lower-priority text. Hero title alone, topic subtitle alone and a TOC alone correctly do not select the structured body. Original source revisions remain attached to refused offline plans.

Verification: actual registered-handler review/commit/reopen, exact source race, forged candidate hash, revoked authority, unsupported source precedence and no-write refusals pass alongside the existing canonical tests. Pure converter tests use actual generated schemas and preserve marks/blank paragraphs/list state/code. Backend types passed `/tmp/canonical-authored-migration-types2.log`; packaging checks prove the new 19-file deployed closure and 15-file portable closure remain isolated. Offline API generation found 740 modules and compact generation produced 2039 functions / 2347 terminal DTOs / 429 existing unknown boundaries. No live migration or publication is claimed. Root deploys immutable snapshots separately.

Public v2 transport/publication/scheduling, supported authored block/structured-data migration, canonical duplication/promotion and full visibility/locks/treatments remain required follow-on work. The private document DTO stays draft-only until its proper publication/editor transition is implemented together with the Website consumer.

The later [canonical publication source checkpoint](canonical-publication-outcome.md) supersedes the draft-only/private-DTO and unavailable-publication statements above: actual public v2 read, publication and scheduling are now implemented and locally tested. Broader authored migration and canonical duplication/promotion remain open; no live acceptance is inferred from the source checkpoint.
