# Commerce promotion adapter design

This adds product/category/variant record kinds to the existing reviewed authored unit. Product-showcase and the supported product/category catalog blocks discover the bounded source catalog and its media, categories, parents and variants. Explicit product references become authored records. Existing target-only references remain possible through the original dependency binding contract.

Prices carry explicit nonnegative minor-unit amounts and uppercase currency codes; review verifies target store currency and sales consistency. Allowlisted fields cover titles/slugs/SKUs, descriptions, publish state, media, category membership, physical dimensions/tax flags, product type, local option names/values and variant selections/default ordering. No source user IDs, inventory quantities/controls, provider identifiers, licensing/download bindings, arbitrary metadata or delivery records enter the manifest. Unsupported tags/global attributes/digital/external associations fail explicitly. Current schema has no product tag storage or assignment model; promotion will not invent one.

New physical products are tracked at zero stock with backorders off. New variants use managed zero stock, out-of-stock status and no backorders. Existing target operational fields and identities stay intact. Product type and delivery-kind changes or unreviewed variant/category collections block. Local option identifiers are reconstructed for new records and preserved by matching existing option names/values; source database IDs are never used. Variants resolve through product mapping and stable SKU/selection identity; duplicate target or source SKUs/selections/defaults block review.

Categories map by slug, recursively remap parents, and retain counts. Publication/category changes update derived direct/ancestor counts atomically within the reviewed category set. Existing parent/subtree moves or collection removals outside that set require a separate adapter. All changed category rows are included in backups. Search text is derived locally; no hooks/events/search jobs or outbound integration actions are replayed. The existing plan fingerprint/expiry/operator/target checks and update-only rollback protections remain.

The current 100-record/500KB atomic unit and bounded scans still apply. Plans/courses/digital delivery, tag storage, external/global attribute catalogs, collection deletion and large-graph orchestration remain explicit follow-up work. No deployment or live calls are authorized for this subtask.
