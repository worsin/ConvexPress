# Canonical duplication source checkpoint

`canonicalDocuments.duplicate({postId, expectedRevision})` creates a new draft and returns the existing write receipt with the new post ID, revision 1 and canonical title/tree digest. The existing `posts/mutations.duplicate` accepts optional `expectedRevision`: supplied revisions dispatch immediately through the canonical service; ordinary v1 callers retain the previous handler. V2 requests without a revision refuse explicitly. The actual editable admin list already carries `blocksVersion` and `blocksRevision`; a registered-query regression verifies the native list can provide the correct CAS value.

The service requires existing `post.duplicate` capability plus the ability to edit the entire source. It checks current v2 format, status, exact revision, generated tree, current presentation/plugin policy, referenced data and media before preparing a destination. It preserves marked text, children, layout/anchors/inactive lock fields, complete authored snapshot fields, metadata, taxonomy assignments, custom fields, source password and protected visibility. The new draft has a distinct slug/path, current operator owner, fresh timestamps and revision 1. No source autosave, publication deadline/job, publication timestamp, edit lock, comments or source history is transferred. Source status private becomes destination visibility private. The source row remains unchanged.

The existing policy-copy helper remains authoritative. Direct rules retain their groups; each route alias's independently evaluated policies receive distinct groups on the new document, preserving the prior conjunction semantics. Customer identity and membership grants are never copied. Its new optional request ledger forwards through the already measured membership reads and homepage-alias settings read without changing legacy callers or policy evaluation.

Copy inventories use exact post/entity indexes and request at most 257 rows, refusing when more than 256 appear; total copied relationships are limited to 512 and source/copy material to two MiB. These are explicit complete-inventory refusals, not silently capped copies. The canonical request ledger separately measures full returned raw documents, including policy/settings reads and media guard reads. Slug lookups and reserved-page route checks accept the same optional ledger; ordinary callers retain their behavior. All owner inserts use existing media guards and the exact internal canonical permit. An unavailable custom-field media reference rolls back the entire transaction, including earlier destination inserts. No reverse-index bypass is introduced.
