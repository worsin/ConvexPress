# C04 archive helper — streaming implementation outcome

Implemented `packages/control-plane/convex/operations/remoteSnapshotArchive.ts` and its regression suite. Root owns the action/export/import integration and native/fleet acceptance.

The helper exposes `inspectRemoteConvexSnapshot`, `verifyRemoteSnapshotChecksum` and `prepareRemoteTargetBoundSnapshot` using the agreed contracts. It reads SHA-256 incrementally, validates optional HTTP Digest, parses storage inventory as JSON lines without retaining the inventory, and uses yauzl RandomAccessReader with validated HTTP Content-Range and bounded one-MiB blocks (four cached blocks). HTTP bodies use the shared idle/length-limited reader. Unsupported range servers fail closed.

Every read prefers a strong ETag with If-Match. A generic URL without one is rejected. The sole fallback is explicit `immutableStorage:true`, which the action caller may set only for a URL obtained from an already-validated immutable Convex storage ID. This keeps preflight checksum/identity verification bound to the bytes subsequently imported.

Preparation verifies both complete artifacts and expected source/target identity before returning a stream. It preserves the target identity, management authorities and schemas, rebinds synthetic operator IDs after removing source-local user IDs, and clears target sessions/nonces. Raw compressed content entries stream into fflate ZIP output without complete-file inflate/recompression. Output follows consumer demand; no local disk is assumed. Existing byte-array APIs remain compatible for callers/tests that still use them.

Explicit capacity gates: 3 GiB ZIP32 source/output, 20,000 entries, 512-character safe paths, 16 GiB declared total expansion, 8 MiB aggregate target management metadata, 64 KiB site identity, bounded metadata rows and one-MiB JSON-line length. Duplicate/traversal paths, unsupported encryption/compression, malformed metadata, required-entry CRC errors and ambiguous identity fail closed. Normal content entries retain their original compressed data and CRC; their immutable whole-artifact checksum is checked before import.

Verification: all 43 operation tests passed, including five new remote archive tests. A valid 600 MiB virtual archive (generated as ranges, never held whole) passed complete source hashing, preparation, streamed ZIP output, an RSS-growth gate below 160 MiB, and paused-consumer backpressure. Small archives are unzipped afterward to prove content transfer, target identity/authorities, numeric Convex JSON semantics and session reset. Negative cases cover range rejection, ETag changes, Digest/checksum mismatch, incorrect identity, malformed archives, traversal, duplicate paths, CRC corruption, encryption and declared oversized entries. Scoped diffcheck passed. The latest full control-plane TypeScript run reported only the concurrently edited root-owned `snapshotImportApi.ts` BodyInit type issue; the new helper/tests produced no TypeScript errors.

No real backup, restore, promotion, provider mutation or native app launch was performed by this station. Actual Convex storage Range behavior and packaged fleet operation acceptance remain root's integration checks.
