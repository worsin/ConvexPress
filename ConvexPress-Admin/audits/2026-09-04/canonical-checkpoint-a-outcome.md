# Canonical checkpoint A: registered document lifecycle

Source checkpoint: 2026-09-05. This is the first registered backend/native-editor contract, not completion of the unified block rollout. No canonical endpoint deployment, live write, provider call or browser acceptance was performed by this agent. Root owns coordinated deployment and the disposable Aster staging acceptance.

## Implemented source

`packages/backend/convex/canonicalDocuments.ts` exports authenticated `get`, `initialize`, `save`, `restore`, `pageRevisions`, and `pageOptions`. All functions have finite registered types and explicit Convex argument/return validators. Return shapes are derived from the authoritative pure Zod DTOs; the full tree/data/resource parser additionally enforces refinements, exact identity and byte budgets. The native consumer imports those same pure contracts.

- `get` returns either the closed initialization discriminant for legacy content or the fully validated current v2 draft with installation identity, presentation fingerprint, trusted installed policy, attrs-bound public `content.page` data and exact referenced media. Optional `refreshKey` accepts 1–64 ASCII alphanumeric/underscore/hyphen characters; it only distinguishes explicit server refreshes from subscribed client-cache results and never grants authority. Normal reactive queries omit it.
- `initialize` requires an empty existing editable legacy draft, current revision and complete authoring digest. It preserves unrelated authoring metadata, routing, ownership and restrictions; snapshots the original state; validates the candidate; and writes v2 with the next revision. Explicit empty initialization followed by a fresh read supplies the server policy before adding blocks.
- `save` checks the current revision before equality. An identical current candidate is a no-op; a stale identical candidate conflicts. Changed saves validate the full generated tree, policy, public data bindings and media, snapshot current authoring, and advance the current revision. Clearing legacy autosave state cannot bypass the shared version fence.
- `restore` requires `revision.restore` and current editorial authority, exact parent and v2 history. It restores the full supported authoring snapshot (including root's layout/prompt snapshotVersion2 fields), writes a safety snapshot, and advances the **current** revision rather than reviving a historical number.
- `pageRevisions` and `pageOptions` use indexed pagination, 1–20 requested rows and server 256-row/512-KiB read limits. They retain ordinary empty continuations, optional inert split cursors and other official pagination metadata. SplitRequired refuses explicitly. Page options contain only discoverable public published pages, never authored bodies or customer identities. History titles are validated without truncation; actual restore revalidates its selected full row.

The shared query/mutation ledger charges full returned auth/session/user/role/plan/policy/settings/post/media/edge documents, including fields omitted from DTOs; it charges each read before execution and prevents the next dependent read after exhaustion. Limits are 256 reads, 2,048 documents, 8 MiB aggregate returned document bytes and 512 KiB per document. Indexed policy queries additionally enforce their own engine read budgets. This does **not** equate returned document size with internal index-engine memory or establish a cross-request budget. Media hooks thread the same optional ledger through prior-owner, attachment and reverse-edge reads; ordinary callers retain their existing signatures/behavior. No generic context proxy or cross-call mutation cache was added.

Before mutation writes, the complete prospective post is measured with official `getDocumentSize`, including preserved metadata. Revision candidates also reserve 512 bytes for system-field overhead. This closes a reproduced failure where a valid 480 KiB block tree plus a preserved 40 KiB prompt would otherwise save successfully and then exceed the reader's 512 KiB limit. No state is written on refusal. History retention is not collected or pruned in this request.

## Storage and compatibility

The storage node validator is mechanically emitted from the existing closed canonical node schema by `scripts/blocks/storage.mjs`. The posts/revisions schema accepts legacy and canonical structural envelopes; supported authoring services enforce the `blocksVersion` discriminator and full generated attrs/tree semantics before writes. This is not a blanket `any` replacement of the stored envelope.

The existing source-level one-use canonical permit is now exercised by the real service and media wrappers. Ordinary posts/pages edits, autosave and legacy revision restore refuse v2 authoring changes. The legacy block reader refuses v2 instead of flattening `children`, layout and anchors. Usage projection now selects the matching tree vocabulary and counts repeated canonical descendants once per document. Source promotion refuses v2 before legacy `pickData` can discard the discriminator; planning refuses a legacy import over an existing canonical target; actual write/rollback wrappers remain fenced. Root's duplicate handler is still deliberately v1-only.

Canonical status transitions to publish/future/private/pending/auto-draft are unavailable at this intermediate gate. Trash and recovery semantics remain separate. Active locks, non-everyone visibility and named styles remain explicit unsupported-feature refusals; direct attempts to add a lock or remove an unsupported stored lock cannot silently pass. These fields being present in the type is not an implemented feature claim.

Backend deployed contract copies normalize only module filenames and relative imports to Convex-safe underscores. Root's first immutable snapshot rejected hyphenated module names before any push; `scripts/blocks/convex-module-paths.mjs` and the deployed generator now enforce the supported paths. Root/staged/Website source names remain unchanged. Generated closure checking validates deterministic transformed content, managed inventory and independently loadable imports. No generated backend module imports the repository root or Website graph.

### Native empty-draft autosave compatibility repair

Root's actual create → Save Draft → reopen flow retained `autosaveTitle` equal to the saved title, which incorrectly made an otherwise empty draft ineligible. The pure initialization policy now recognizes only exact redundant autosave title/body values. Distinct autosaves, including clearing a nonempty title, remain protected; all autosave fields remain in source CAS hashing. Actual handler regression proves eligibility, stale/distinct refusal, canonical commit and original saved title/body revision preservation. Red-to-green tests: 20 tests / 107 assertions; backend types pass (`/tmp/canonical-redundant-autosave-types.log`). No live acceptance is claimed by these tests.

A minimal patch against the captured canonical-lifecycle backend is at `output/canonical-checkpoint-a/redundant-autosave-fix/snapshot.patch`, with base/fixed file hashes in `files.json`. It changes the deployed pure documentState module and its generation manifest only; no API, storage schema, renderer or unfinished migration work is included.

### Immediate manual-save reconciliation

The next real native save exposed an asymmetric older behavior: pages.update kept obsolete autosave values; posts.update cleared all values, including distinct recovery content. Both now call the same pure transaction-local reconciliation helper for supplied title/body saves. It clears only an entire present autosave pair matching the previous saved pair or resulting saved pair. Mixed/distinct pairs survive intact; metadata-only updates do not acknowledge them. An already-ambiguous older fixture is not retroactively cleared.

Actual page and post update → immediate canonical eligibility tests pass, including distinct autosave preservation. Combined focused gate: 25 tests / 148 assertions; backend types pass (`/tmp/canonical-manual-autosave-types.log`). Minimal snapshot delta against canonical-lifecycle-autosave-20260905 is `output/canonical-checkpoint-a/manual-save-autosave-fix/snapshot.patch` (one helper and two update call sites), with hashes in files.json. New migration code is excluded from that patch. Native acceptance remains root-owned.
