# Canonical legacy compatibility and editorial treatment — source checkpoint

The previous migration service accepts structured TipTap articles and refuses legacy block/section/structured-post sources. The new source foundation preserves the actual old schema and render-default behavior without importing legacy registries or renderers into the deployed application graph. It does not yet remove those service refusals or claim full authored migration acceptance.

`scripts/blocks/generate-legacy-compatibility.ts` discovers all 54 existing legacy definitions and bundles their exact saved and Website Zod schemas, including refinements and defaults. Its inputs are an explicit discovered schema closure; runtime imports are only Zod. The output manifest hashes the original schemas, canonical specs, helper and bundled files. Two independent builds must match, and `check:blocks` now checks this artifact for drift. The compatibility output stays out of the Website portable data bundle. The exact historical `pageSectionsToBlocks` implementation is also bundled; callers must validate stable IDs first so its random fallback never runs.

`legacyBlockMigration.ts` performs bounded, pure same-installation conversion: rejects unknown authored and envelope fields before Zod can strip them, uses actual Website defaults, applies declared empty/richtext/design transforms, preserves IDs and child order, and validates the complete resulting canonical tree. Unsupported versions, active locks, incompatible layout, unknown design mappings and invalid target values fail the entire candidate. It does not execute arbitrary Markdown/HTML or resolve identities by guess. No source object is modified. The existing service remains responsible for access, exact source CAS, full original safety revision, current media/policy/pack validation and review before a write.

Root approved a separate optional instance `treatment: {name, values}` beside attrs/style/layout. The first treatment is FieldGuide `editorial`: spacing integer 0–8, alignment left/center/right, ink foreground/primary/muted, font body/display. Specs declare finite axes/defaults; all values are explicit in a persisted treatment. Generated validators reject unknown names, missing/extra axes and invalid combinations. `TreatmentByName` correlates each block name with its valid treatment. Convex validates a finite string/number storage shape; every authoring path still requires generated full validation. Four pack manifests explicitly declare support and the renderer owner implements their exact semantic-token mapping. Backend private/public projection calls generated `assertPackTreatments` before resolver/media reads, so an unsupported active pack cannot silently drop treatment. Named style remains independent. No 162-item public style registry or raw CSS field was introduced.

`legacySectionMigration.ts` stages the exact seven-kind old section projection with strict source preflight. It retains historical selected heading/body fallback behavior; it refuses unknown source/row properties and old coercions. Nonempty authored shell intent remains unsupported until its exact treatment adapter exists. The original revision will retain all source fields, including source-shadowed fields. Structured blog article conversion and supported lock/visibility semantics remain unfinished; they are not represented as plain-text fallback.

Source tests prove all 54 saved/rendered schema sample results against actual imported source, deterministic bundle closure, every 162 editorial combination, wrong-block/pack and malformed-axis refusal, unknown/nested authored-field refusal, seven section projection parity cases, and literal old rich-text grammar. Renderer equivalence and actual API migration of these newly supported sources remain the next activation gate. Root owns deployment and real native/public acceptance.

Final source checkpoint for this slice: 56 block tooling tests / 4351 assertions and 67 canonical foundation/actual-handler tests / 466 assertions pass; backend TypeScript is green. `check:blocks` passes with 136 specs, four packs, exact compatibility source hashes, portable 18 files and deployed 28 files. The deployed pure closure uses Convex-safe module names. Logs: `/tmp/canonical-compatibility-final-block-tests.log`, `/tmp/canonical-compatibility-final-tests.log`, `/tmp/canonical-compatibility-final-types.log`, `/tmp/canonical-navigation-check-blocks.log`. API/compact generation remains with the media epoch owner for the next combined checkpoint.

Structured-post investigation confirms an additional rendering boundary: visible topics are filtered before indexing, and their TOC anchors use those filtered indices or the historical title slug. Hero title alone is not displayed; TOC alone does not select structured mode. Body paragraphs preserve their original interior/edge text while linkifying bare HTTP(S) URLs; the historical renderer also interprets HTML/entities via innerHTML. A safe adapter must preserve that behavior only through an explicit supported HTML/inline contract, refusing unrepresented input. Generic iframe normalization and section typography/spacing also require reviewed adapters; current canonical schemas alone do not prove their equivalence.
