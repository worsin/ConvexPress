# Course and membership authored promotion outcome

Implemented in canonical source; verified offline. No deployment, provider calls, live reads/writes, browser/native tools, commit or push were performed by this agent. Design: [content-promotion-learning-design.md](content-promotion-learning-design.md).

## Adapter

The existing promotion protocol now supports five additional authored record kinds: `course`, `courseNode`, `coursePrerequisite`, `plan` and `planBenefit`. These use the actual existing `lms_courses`, `lms_nodes`, `lms_course_prerequisites`, `membership_plans`, and `membership_plan_benefits` tables. Optional `courseIds`/`planIds` selection fields are backward compatible. No new content model, tables, queues or alternate context/schema bridges were introduced.

Course export includes the complete bounded curriculum, prerequisite graph, media and course restrictions. Course/product/page/block restrictions resolve authored or explicitly bound target membership plans; menu plan slugs discover authored source plans. Course and plan identity maps by durable source mapping or unique slug, nodes by durable mapping or unique course/parent/kind/title, prerequisites by mapped course pair, and benefits by mapped plan/code. Ambiguous target matches fail. Existing nodes cannot change kind or move parent/course; all existing child/prerequisite/benefit collections must be reviewed. Prerequisite cycles, malformed curriculum, duplicate positions/benefit codes, missing parents, invalid drip dates and dangling/inactive plan gates fail before apply.

Supported authored course fields include descriptions/materials, lesson bodies, public media/video references, normalized category/tag labels, publication, open/free/members/closed access, progression, dates, drip and learner-facing completion controls. Course counts are derived from the reviewed tree. Members courses require an included plan-backed gate. Paid/recurring/external course delivery and certificates remain explicit adapter refusals, including existing target configurations, rather than becoming free courses accidentally.

Plan titles, slugs, status, grant mode, priority and benefit display fields are reviewed. New plans must use manual grants. Subscription/purchase/hybrid plans need a compatible existing target plan; promotion cannot change its grant mode or invent billing links. Existing target subscription codes, linked roles/capabilities and benefit metadata remain untouched. Source role/capability bindings and nonempty-or-empty benefit metadata fields require an explicit semantic binding adapter and are rejected instead of being silently discarded.

Source author IDs, enrollment rows, user grants, progress/completions, payment/provider records, certificate issues, AI jobs, and lesson edit history never enter the authored manifest. Existing target learner/member records remain byte-for-byte intact in handler tests. Source and target plugins and ordinary LMS authoring capabilities are checked, including Editor access for another author's course. Target fingerprinting catches concurrent billing/content edits. Apply/retry and guarded update-only rollback remain atomic. No events, hooks, schedulers, outbound integrations, search jobs or automatic enrollment/grant replay occurs.

## Runtime prerequisites and remaining work

Deploy updated source and target site backends plus the shared contract package. No data migration or provider setup is introduced by this adapter. LMS and Membership must be explicitly enabled where used; authoring operators need the normal LMS create/edit/publish/builder/lesson capabilities in addition to settings management. Manual plan creation grants no users access by itself; normal enrollment and grant APIs remain authoritative.

Paid/recurring/external course checkout, certificates and assessment/question structures, subscription pricing/billing catalogs, explicit role/capability/benefit-metadata bindings, capability-only course gates and route-wide membership rules remain outside this bounded adapter. Existing target paid plan linkage is preserved, but new billing linkage is never synthesized. Unknown dynamic LMS block catalogs still fail with `CATALOG_ADAPTER_REQUIRED`; no hypothetical block renderer was invented to bypass that refusal.

Collection deletion/subtree moves, created-record rollback and uploaded-blob cleanup, durable resumable transport/orchestration and large-graph promotion remain pending. Atomic units retain the 100-record /500 KB UTF-8 limit and bounded collection scans. No grant, enrollment or completion is created merely because authored content was promoted. Live source/target preservation, UI review and rendered Aster acceptance remain root-owned work.
