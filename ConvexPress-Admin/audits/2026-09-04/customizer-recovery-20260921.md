# Customizer draft recovery — September21

Unsaved on-site Customizer work now survives removal of the operator provider. The recovery copy stays in the current tab's memory, outside the authenticated subtree, and is scoped to the authenticated profile ID, backend URL and environment. It contains the selected pack, authored values/variants, bounded Undo/Redo history and original published/private-draft revision guards. It grants no authentication. Inactive generations cannot read/write it, and another owner clears the previous copy.

The panel restores after the backend accepts a fresh session for the same operator. It never rebases a recovered draft onto a competing publication or publishes automatically. Explicit discard clears recovery. End editing confirms before discarding dirty work; beforeunload requests the browser's unsaved-work warning. Expiry guidance is visible inside the mobile panel. Late save/publish acknowledgements cannot close or erase a newly mounted editor. The on-site gate now waits for Convex authentication as well as profile capabilities, preventing a cached profile from opening recovery before the new token is accepted.
