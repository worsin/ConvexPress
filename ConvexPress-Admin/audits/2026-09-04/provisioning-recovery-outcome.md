# C03 — provisioning recovery outcome

Implemented in the isolated hardening worktree, without deploying or launching the app.

- `desktop/electron/deployment/journal.ts` atomically persists versioned, mode-0600 phase receipts under Electron userData. Reads validate the schema and fail closed on corruption. Receipt fields exclude credential/token values, CLI arguments, environment values, raw output and raw error messages. Completed obsolete receipts are pruned at the 500-run ceiling; current target identity records remain protected.
- `siteDeploy.ts` resolves credentials before taking a canonical-origin target lock. Independent targets can proceed; shared extension generation is serialized. Repeated initialization must retain recorded website/environment identity. Retry keeps its run ID and increments its attempt; unfinished runs become interrupted after restart. No deployment resumes automatically.
- Child PID/process-group receipts survive restart. A recorded live process keeps its target blocked; the app does not kill potentially reused PIDs. A retry waits for that process to disappear. Commands receive ten-minute deadlines, each run a thirty-minute deadline, and IPC cancellation terminates child process groups. API/health calls have explicit deadlines. The shared adapter calls C02's packaged runtime resolver and clears inherited deployment selectors.
- Captured command output is bounded to 256 KiB per stream; environment inventory rejects overflow so a truncated list cannot trigger signing/encryption-key replacement. Initialization preserves existing signing and encryption keys and refuses failed environment reads. Generated secret error messages are scrubbed before leaving initialization.
- Retry checks enrollment after matching site health/identity. A sole connected/healthy credential-bearing connection is reused; pending/ambiguous connections require reconciliation. This avoids duplicate enrollment after a lost success receipt. Ordinary errors now report correctly after fixing recursive `describeFailure`.
- Initialization reads durable target status on mount, filters progress by origin, and exposes retry/cancel. Clerk deployment progress also filters by selected target. The protected preload offers target status, history and cancellation; sender regressions cover the added channels.

Verification: the full desktop suite passed 69 tests before the final complete-output/receipt-failure test; that additional test passed with the other process tests (3 total). Desktop Electron TypeScript passed. Admin web TypeScript passed after progress integration; final scope verification is also run by root. New actual-handler regression covers ordinary failed deploy/retry, same-target exclusion, concurrent sibling target, cancellation, credential redaction, inherited target removal, encryption/signing preservation and completed-connection reuse. Real temporary journals test restart at all five phases, corruption and live subprocess locks. Harmless actual Bun child processes test deadlines, cancellation, capture overflow and persistence failure termination.

Limits: target locks are local to this desktop journal; they are not a fleet-wide distributed lease. A crash between spawning a child and writing its PID is a narrow uncertain window; replay reconciles keys/identity/enrollment and never automatically starts infrastructure work. Pending remote enrollment is surfaced for repair, not guessed completed. Windows taskkill behavior and rendered packaged-app recovery need root's native acceptance; no Windows runtime was available to this station. No live deployment/fleet acceptance is claimed.
