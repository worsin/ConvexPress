# Structured article and inactive legacy intent — bounded pure implementation

These helpers are outside the active Convex graph and are not copied into generated/portable/deployed output during root's navigation/treatment browser freeze. They do not enable migration, change saved documents or grant lock authority.

`canonical-blocks-foundation/legacyStructuredMigration.ts` implements a deterministic semantic conversion of supported structured post fields. The result contains the exact validated original source, a generated-schema-validated canonical tree, explicit non-rendered source paths, and required presentation bindings. Bindings include block ID/name/version, direct child IDs, original source path and finite semantic role. A caller cannot call this complete rendering equivalence merely because the tree validates: its presentation state is explicitly `requires-reviewed-adapter`.

The conversion follows the actual legacy order Hero → Table of Contents → filtered Topics → Summary → Sources. Hero title alone, subtitle-only topics and TOC alone do not select structured mode. Topic anchors use the filtered rendered topic indices and historical title-slug grammar; duplicate anchors and TOC links beyond existing topics produce path-bearing diagnostics rather than invented IDs or silently dropped links. Images retain source IDs and original alt semantics, including the empty-title/nullish-alt distinction. CTA text/href/new-tab behavior is retained only when both source halves render; unrendered fields remain in the exact original source. Bare HTTP(S) body/source links preserve the authored text and target. Source lines/paragraphs retain their respective historical trim/split behavior.

The required finite presentation roles cover root/topics spacing, hero/topic/summary/source/body/TOC wrappers, hero/topic subtitles and images, and CTA. Current legacy typography includes 32px outer rhythm, 16px hero/body paragraph rhythm, 12px topic/summary/source rhythm, 14px/21px body text, distinct subtitle sizes, hero bleed/aspect and numbered TOC/source semantics. Content owner proposes a closed article group treatment with path/type-bound descendants; that contract is not added or activated yet. Generic automatic iframes remain an explicit provider/consent boundary. The old renderer interprets HTML/entities through innerHTML; current pure conversion refuses unsupported interpretations rather than executing or flattening them. Root has assigned a separate real HTML escaping repair to the content owner. This adapter must adopt that exact safe helper/grammar once available, so newly literal safe text is represented faithfully rather than retaining obsolete refusals.

`legacyIntentMigration.ts` validates all known old block layout, section shell and lock fields. Actual current legacy readers ignore/strip layout/shell and never enforced lock flags. The plan therefore distinguishes original saved intent from effective behavior. Semantic mappings are explicit: contrast→inverted, normal padding→default spacing, content container→contained width, and exact compact/spacious/wide/full values. Legacy container and align can conflict; no precedence is invented. Target support is checked. `resolveLegacyIntent` requires an explicit `preserve-current` or `apply-saved` decision, preserving the full original values in either result. Applying saved values changes presentation/edit policy and is not an automatic lossless interpretation of ignored legacy fields. A conflicting width needs a concrete reviewed width; unsupported target fields need a supporting wrapper, not dropping values.

`lockTransition.ts` implements the pure candidate guard for eventual active locks. Remove locks block removal through an ancestor. Move locks preserve the parent and relative order among retained siblings, while allowing unrelated insertions/deletions before a node. Edit locks protect the full node content and descendants. Flag changes need a separate trusted, strictly boolean `mayChangeLocks` decision. The old lock remains effective for the current transition: unlocking and editing protected content cannot be combined to bypass it. Remove/edit are distinct; an edit-only lock does not invent a remove lock. Input byte/node/depth/unique-ID bounds are enforced. This is not yet wired into save/restore/migration, and no existing capability has been reinterpreted or new capability invented. Root must choose the authority policy before activation, then all direct API writers and native controls must consume the same guard.

Seven focused pure tests / 63 assertions pass: actual source selection/order, source retention, deterministic IDs, filtered anchors/TOC, URL targets, unsupported markup/provider/target diagnostics, shell semantic mapping/ambiguity, explicit review resolution, flag forgery/coercion, subtree edits, ancestor deletion and bounds. Staged foundation TypeScript is checked separately. FieldGuide service activation remains held for root's computed-style gate; generated/browser files were not changed by this slice.

## September 5 follow-through

The historical HTML/entity refusal above is superseded: StructuredContent now renders text through React, and the pure converter preserves that exact literal grammar. The actual website URL policy is bundled for CTA conversion; rejected CTA URLs retain their original value and render their label under a new explicit cta-label presentation requirement. Both legacy article renderers now use reviewed embedded-content loading and safe-link fallbacks. The structured converter still refuses videos pending its explicit provider/presentation adapter; it must be updated against the current ArticleEmbed behavior, not the former arbitrary iframe. FieldGuide geometry was separately repaired and browser-accepted; migration service activation remains open for the larger integration.
