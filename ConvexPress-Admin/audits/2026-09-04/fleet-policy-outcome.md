# C05 — scheduled maintenance outcome

Implemented one server-authorized maintenance policy per environment, with full-storage backup schedules, periodic public site-health monitoring, optional retention, deduplicated in-app incidents and paginated history. Policies begin disabled until an authorized operator saves enabled settings. Backup intervals are 1–720 hours, health intervals 5–1,440 minutes, retention 1–3,650 days with 1–100 newest verified scheduled backups retained.

The minute cron dispatches at most 40 due policies. Transactional due-time claims prevent duplicate ticks; backup jobs reuse the durable operation/workflow engine and existing exclusive target locks. Policy provenance is stamped on operations and recorded backups. Disabled or inaccessible hierarchy, disabled policy authors, and lost current RBAC pause scheduling. Worker startup and every scheduled snapshot preparation recheck policy authorization. Deferred backups and interrupted/failed workflows produce incidents. Health leases reject stale results after edits, target changes or revocation. Responses are bounded and deadline-limited; identity and healthy status must match. Public liveness updates site/policy health only: it does not overwrite signed controller-connection health or mint recurring auth sessions.

Retention requires explicit enablement. It processes 25 candidates per transaction, only for verified manual-purpose artifacts created by that policy, from succeeded scheduled operations. It keeps recent/newest backups, skips active website operations and unexpired handoffs, and checks operation snapshot references, pre-backup references, recovery receipts and shared storage IDs before deleting storage. Deletion preserves backup tombstones and maintenance events. Manual, legacy, handoff and pre-replacement backups are outside this deletion policy.

The operations panel now includes maintenance settings, authorization state, in-app incidents/acknowledgment, last/next run information and paginated maintenance events. Backup and operation history use paginated server queries and load-more controls. Secret fields never appear in policy/event APIs. UI editing requires current backup and connection-management privileges, including the live-environment guard where applicable.

Verification: full control-plane suite passed **125 tests, 0 failures, 419 assertions**. Eight new actual-handler tests cover scope and optimistic revisions, concurrently invoked tick deduplication, independent environments, disabled parents/operators and explicit RBAC deny, health leases and recovery, page boundaries, bounded health responses, and actual temporary storage deletion while retaining recovery evidence/newest/legacy snapshots. Control-plane and Admin web TypeScript passed during integration; scoped diffcheck passed. Real provider jobs, deployed cron execution, native UI and scheduled-workflow acceptance remain root's fleet checks. This station did not deploy, run backups against a real site, or enable a live policy.
