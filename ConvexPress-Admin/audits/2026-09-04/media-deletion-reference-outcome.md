# Media deletion: atomic bounded repair (2026-09-05)

Source implementation only. No deployment, live deletion, provider call or browser/native action was performed by the implementing agent. This is the first safety slice approved in `media-deletion-reference-design.md`, not completion of scalable media deletion.

## Behavior

- `convex/media/referenceInventory.generated.ts` is generated from actual schema validators: 17 typed media-reference tables, including the two owned metadata tables. Newly covered authored references include variant galleries, revisions, LMS course/node/certificate/issued-certificate media. Scalar fields receive schema-derived indexes in `referenceIndexes.ts`; nested arrays use complete bounded scans.
- `referencePolicy.ts` separately declares conservative authored containers: posts/revisions/legacy reusable blocks, settings/private appearance drafts, legacy layouts/themes, LMS rich text and lesson snapshots, KB article versions/templates. Both canonical `children` and legacy `innerBlocks` are traversed as opaque JSON, without a second block registry. Serialized JSON is parsed read-only, including escaped identifiers; literal IDs in other strings are conservatively retained.
- Each internal `referenceReads` handler owns one pagination journal with server limits of 256 rows/512 KiB and verifies completeness, split metadata and full materialized document size. A mutation shares a 2,000-row/4-MiB/160-read budget, with at most 100 referencing documents/1,000 reference occurrences. Limits are explicit refusal (`MEDIA_REFERENCE_BUDGET`), never a proof that no references exist. Large final documents may already have materialized before the explicit size refusal.
- Single and bulk trash/permanent deletion, HTTP API deletion, trash retention and failed-upload cleanup use the same transactional preflight. Bulk traverses each opaque table once for its selection. Missing/in-use items are classified before writes; unexpected write errors propagate to transaction rollback. No client reference list, old preview or cursor authorizes deletion.
- Force retains the existing Editor requirement. Every clear is prepared before writes, rechecks the actual target value, and only uses reviewed adapters. Gallery arrays preserve unrelated entries and junction removal updates exact album counts. Required-video lessons cannot lose their only video. Opaque or unreviewed historical references refuse with `MEDIA_REFERENCE_UNCLEARABLE`, preserving rich-text/plugin/history semantics.
- Permanent deletion preflights complete size/meta rows, `_storage` metadata and media/mediaSizes ownership. Shared originals/variants survive removal of one library owner. Unexpected storage failures are not swallowed. Size replacement/wipe uses the same ownership policy. Original-image re-encoding now checks and removes old blobs in the mutation, instead of deleting from an action using stale ownership evidence.
- Trash and failed-upload maintenance have separate durable cursors in `mediaMaintenance`, visiting eight candidates per tick. Referenced first pages no longer permanently hide later candidates. A failed preflight does not advance the cursor or perform deletion.

## Writer race boundary

`media/attachmentGuard.ts` provides explicit typed write wrappers, not a context proxy. Referenced media is read in the same transaction as the insert/patch/replace. Active and processing media are attachable; missing/trashed/failed/validating media are refused. Unrelated metadata-only patches skip reference validation. Candidate references include retained fields when a reference-bearing field changes.

Guarded families include page/post and HTTP writers, revisions/autosaves, legacy block/reusable-block mutations, LMS lesson/course/certificate writes and duplication, commerce products/variants/categories, gallery, KB/recipes, template settings/drafts/import, WordPress upserts, profile media avatars, quick drafts and demo-store products. Authored promotion's shared write and rollback boundaries validate media too; an unavailable mapped target cannot be implicitly revived by promotion. `setMediaAttachment` now refuses stale IDs rather than silently returning. Late status/size/metadata processing cannot restore trashed media.

See `media-attachment-writer-inventory.md` for the independent writer audit. This is not a claim that every future extension writer or arbitrary encoding is covered. Plain URL-only embeds, encrypted/base64/custom plugin payloads and external storage references are not decoded into foreign keys. Raw `replaceAll` snapshot imports bypass application hooks. Fixed seed/counter-only writers that introduce no media IDs are distinct from externally supplied authoring writers.

## Required next work

A maintained reverse-reference index, atomically updated by every reference writer, with bounded resumable backfill and a completeness/revision receipt is still required. Deletion must remain disabled for index-based absence decisions until writer coverage and backfill are proven, including raw restore/import invalidation. The bounded refusal in this slice is not the scalable final solution. Historical revision/draft retention and safe removal need an explicit product policy; force currently refuses unsupported history/opaque clearing. Unknown extension/encoded references need generated resolver/writer adapters rather than guesses.

Root acceptance: deploy both sites with the new scalar/storage indexes and internal handlers; use only disposable media to check ordinary refusal, safe scalar force clear, independent owner retention, normal deletion after detachment, and a pending-write/nested-query refusal through a real mutation. Verify a stale picker/import cannot reattach the deleted ID. Do not use authored Aster media as deletion fixtures.
