# ConvexPress Block Kit

Create schema-first Library blocks in `blocks/<namespace>/<name>/`. A single canonical spec generates the authoring controls, types and validation contracts shared by Admin, Website and backend. The Website SDK supplies the baseline renderer and template treatment system.

From the repository root:

```sh
bun run create:block blocks/notice --title "Notice" --dry-run
bun run create:block blocks/notice --title "Notice"
```

This produces a working heading/message starting point, not an implementation of arbitrary prose requirements. Adapt its fields, examples, renderer and tests to the requested purpose. It refuses existing names and never deploys or changes saved content.

For native authoring, start with [the short user workflow](AUTHORING.md). For SDK development, read [CONTRACT.md](CONTRACT.md), [WORKFLOW.md](WORKFLOW.md), [DATA-API.md](DATA-API.md) and [working references](references/README.md). `bun run check:blocks` is the canonical contract gate; `bun run check:block-kit` checks distribution parity for these instructions and scaffold.

The kit provides all eight required workflows in `skills/`: `block-build`, `block-add-feature`, `block-audit`, `block-style`, `block-compose`, `block-promote`, `pattern-build` and `block-migrate-content`. Discoverable copies are generated by `bun run sync:block-kit`. Styling/composition entry points are documented in [style-and-compose.md](references/style-and-compose.md); migration coverage and write boundaries are in [content-migration.md](references/content-migration.md). Skill distribution is separate from end-to-end acceptance. The delivery plan records completed legacy retirement for the named installed corpus; actual AI/provider requirements and final integrated acceptance remain open.

To author a portable starter section, adapt `references/patterns/project-introduction.json`, then run `bun run pattern:build --pack journal --file <your-pattern.json>` to inspect the plan and add `--write` to install it. See the pattern-build skill for editor and rendering acceptance.

Custom-definition promotion uses `bun run promote:block --file reviewed-promotion.json` for a dry run and `--write` for new SDK source. Read [the promotion workflow](references/promotion.md). The latter also passed four-pack rendering, pinned-content preservation and post-promotion revocation; see the repository report `ConvexPress-Admin/audits/2026-09-04/promotion-installed-20261006.md`. These manual trials do not certify actual AI generation or every future block.
