# Structured block AI: current implementation boundary

The generated ai-catalog.ts projection comes from the same136 canonical BlockSpecs. canonical-blocks-foundation/aiCatalog.ts builds a nested tool-input JSON Schema using each installed Zod attribute schema, the canonical envelope and exact versioned custom schemas. Context supplies the active pack, approved definitions, enabled plugins/runtime capabilities, disabled/hidden blocks and styles. Plugin provenance and trusted resolver requirements cannot be weakened by a custom definition. Optional fields keep their input/default semantics. Canonical validators still enforce bounds, URLs, refinements, nesting, anchors and pack treatments after generation; a JSON Schema alone is not authority.

Provider output contains title and a block tree without IDs. Validation supplies fresh IDs, preserves children, and refuses the whole result on an unknown/version-mismatched/disabled block or unsupported field. No filtering/truncation repair is performed. All136 catalog examples have schema/runtime coverage. Metadata and result validation are lazy: they construct only schemas used by a proposal. Full provider JSON Schema is built only when the Node action accesses the schema getter. Constructing every schema inside the database isolate exceeded its64MB memory limit during live acceptance. The generated catalog revision binds complete specs, compiled attribute schema source, field runtime and pack definitions without rebuilding provider schema inside queries.

canonicalDocuments/ai:generateProposal now reads an authenticated, exact-site/revision context, calls the configured provider using a forced named tool and returns a proposal only after reloading authority and comparing the context fingerprint. Discovery uses indexed active custom heads, immutable approved versions and approved older pins in the current document. It refuses an oversized custom library rather than silently truncating it. The fingerprint binds the actor/session, site, document, active appearance, policy, catalog revision and approved definitions. Draft-only custom metadata never enters the provider catalog. No client-supplied catalog or definitions confer permission.

ai/structuredProvider performs one bounded request with a120-second timeout, fixed provider endpoints, redirect refusal and response size limits. It rejects free-text extraction, incomplete output, wrong/multiple tool calls and provider failures without exposing provider bodies or credentials. canonicalDocuments/aiContext:apply rechecks the same context and catalog in the transaction that calls canonical saveDocument, preserving normal resource, publication, revision-history and concurrent-write checks. Generation itself never writes the page.

The native canonical editor now offers a capability-gated proposal review. The proposed document can be edited, previewed without saving, and explicitly applied once. Review does not claim the normal editor recovery lease. Document/template changes and lost permissions discard late results; a save subscription arriving before its own receipt does not destroy the review. `canonicalDocuments/aiContext:preview` rechecks the generation context and projects the unsaved candidate through current resource authorization without committing the page or a revision. Website preview renewal calls this proposal query rather than substituting the saved page.

Acceptance includes DOM tests of editing/preview/apply, cancellation, recovery ownership and the workspace permission gate; native Electron prompt, unsaved-edit protection, cancellation and safe missing-provider configuration; and a deployed public preview query with a synthetic validated nested proposal. The synthetic result is not evidence of external AI generation. Later acceptance in output/live-ai-authoring-20260916 verified external generation, native review, actual unsaved Website preview, single apply and reopen for one Core/OpenRouter case. Its temporary key was cleared afterward; this does not prove every provider or model.

Authors can now explicitly select up to six products and twelve media items with the existing scoped pickers before generation. The server reloads the selection and sends only approved product IDs/titles/slugs or media IDs/filenames/alt text/MIME types. Product metadata, prices, media URLs, storage IDs and uploader data are omitted. The context fingerprint binds these authoritative labels and IDs; permission, publication, membership and media availability are rechecked before generation and after the provider returns, and again for preview/apply. Provider-generated references must match a saved reference or a selected resource of the correct kind/storage, including generated nested field paths and custom dependency descriptors. Human review can still choose new authorized resources through normal editor pickers.

Live acceptance used three disposable products and the actual public preview query with a synthetic validated tool result: current prices rendered in the result and changed when the middle product price changed, without saving the page. Native Electron selection/removal/reselection, media picker cancellation, discarded-selection cleanup and the missing-provider message passed. This is not successful external generation or rendered comparison acceptance. A temporary role grant exposed a stale management-session ceiling in the client permission display; reopening the environment refreshed the session, while the backend correctly refused the old session.

Later output/definition-ai-compose-20260916 and output/definition-ai-style-20260916 prove one Journal/OpenRouter custom creation and styling flow, including editable fields, preview and save. Remaining: resource discovery directly from an unqualified natural-language request, broader provider/dynamic-data acceptance, outstanding pack vocabulary acceptance and resolver/media/child-slot SDK promotion. Static Studio Services promotion now has native end-to-end acceptance. The explicit product/media selection path is implemented, but is not the complete handoff workflow.

The existing flat legacy AI actions are still present. Their reads now require blocks.ai plus current document edit authority. Proposal returns recheck access/enablement, and each additional variant provider call rechecks access. The internal AI write mutations require current blocks.ai, enabled block types and revision matching in the same transaction as the write. Regeneration without an explicit revision uses the pre-provider revision. Ordinary manual writes do not inherit an AI requirement. Legacy UI controls respect the capability; stored roles are not silently changed.

Verification lives in output/structured-block-ai-20260916 and output/canonical-ai-context-20260916; inspect the latest receipts rather than inferring live success from test coverage. Actual-schema and delayed-provider regressions exercise permission revocation, disablement and concurrent edits. Live isolated-target probes refuse all six legacy AI action entrypoints for an operator without blocks.ai and leave the document unchanged. These denial probes are not successful provider-generation acceptance. Source-based custom authoring, all pending block/pack visual and interaction acceptance, and the full original production objective remain required.
